# 所有权与借用

## 要解决的问题

Rust 没有垃圾回收器，但仍然要在运行时避免悬垂指针、重复释放和数据竞争。它把“谁负责释放值”变成了类型系统的一部分：

- 每个值在同一时刻有一个明确的 owner。
- owner 离开作用域时，值被自动释放。
- 其他代码通过借用访问值，而不是复制所有权。

这也是后续理解 [[Rust学习/01-核心语义/生命周期|生命周期]]、迭代器和并发的基础。

## 核心规则

### move：所有权转移

`String`、`Vec<T>` 等类型通常拥有堆内存，赋值或传参会转移所有权：

```rust
let first = String::from("rust");
let second = first;

// println!("{first}"); // error[E0382]：first 已经 move
println!("{second}");
```

这不是浅拷贝。转移后只有 `second` 负责释放同一份字符串数据，避免两个变量在离开作用域时重复释放。

### Copy：按值复制

整数、布尔值、字符以及只由 `Copy` 成员组成的简单类型可以按值复制：

```rust
let a = 10_i32;
let b = a;

println!("{a} {b}"); // 两个值都仍然可用
```

`Copy` 不是“所有类型都可以随便复制”的开关。拥有堆资源的 `String` 不能实现 `Copy`；需要显式复制时使用 `clone`：

```rust
let a = String::from("rust");
let b = a.clone();

println!("{a} {b}");
```

### 借用：访问但不取得所有权

不可变借用用 `&T` 表示。可以同时存在多个不可变借用：

```rust
fn length(text: &String) -> usize {
    text.len()
}

let text = String::from("borrow");
let size = length(&text);
println!("{text}: {size}");
```

通常参数写成 `&str` 比 `&String` 更通用，因为 `String` 和字符串字面量都可以借用成字符串切片：

```rust
fn first_word(text: &str) -> &str {
    text.split_whitespace().next().unwrap_or("")
}

let owned = String::from("rust language");
let literal = "rust language";
println!("{}", first_word(&owned));
println!("{}", first_word(literal));
```

### 可变借用

可变借用用 `&mut T` 表示，并且要求 owner 本身是可变的：

```rust
fn append_suffix(text: &mut String) {
    text.push_str("!");
}

let mut text = String::from("rust");
append_suffix(&mut text);
println!("{text}");
```

同一作用域内，不能同时存在一个可变借用和其他仍在使用的借用：

```rust
let mut numbers = vec![1, 2, 3];
let first = &numbers[0];

// numbers.push(4); // error[E0502]：numbers 仍被 first 借用
println!("{first}");
```

### 借用的两条互斥规则

在同一时刻，满足下面二者之一：

1. 可以有任意多个不可变引用。
2. 只能有一个可变引用。

引用必须始终有效，不能比它引用的值活得更久。编译器会根据实际使用位置判断借用何时结束，这就是非词法生命周期（NLL）带来的常见体验：

```rust
let mut values = vec![1, 2, 3];

let first = &values[0];
println!("{first}"); // first 的最后一次使用在这里

values.push(4); // 之后可以再次可变借用
```

## 切片是借用

切片 `&[T]` 或 `&str` 不拥有底层数据，只保存一段连续区域的视图：

```rust
fn sum_prefix(values: &[i32], end: usize) -> i32 {
    values[..end].iter().sum()
}

let values = vec![2, 4, 6, 8];
println!("{}", sum_prefix(&values, 3));
```

切片的长度在运行时保存，因此函数不需要知道底层容器是数组还是 `Vec`。

## 编译器视角

- `E0382`：使用了已经 move 的值。检查赋值、函数传参和循环是否转移了所有权。
- `E0499`：同一时间创建了多个可变借用。把借用范围缩短，或改为一次修改。
- `E0502`：不可变借用仍在使用时尝试可变借用。先完成读取，再进行修改。
- `E0596`：通过不可变绑定创建可变借用。需要将 owner 声明为 `mut`。

修复借用错误时，不要先机械地添加 `clone`。先确认真正需要的是：

- 转移所有权；
- 只读借用；
- 可变借用；
- 还是调整数据结构，让某些值不必同时被读写。

## 常见误区

- `let b = a` 对 `String` 是 move，不是深拷贝。
- `&mut T` 不是“可以无限修改”，它仍然只能在独占借用期间使用。
- `clone` 会产生实际复制成本，不应作为借用设计的默认修复。
- `&String` 通常可以改成 `&str`，让接口接受更多输入类型。
- 借用检查器拒绝代码，往往是在提醒数据流或作用域设计不清晰。
