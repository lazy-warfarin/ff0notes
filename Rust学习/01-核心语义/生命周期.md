# 生命周期

## 要解决的问题

借用只在被引用的值仍然有效时才安全。生命周期标注告诉编译器多个引用之间的有效期关系，避免返回悬垂引用。

生命周期参数描述的是“引用之间的关系”，不是给值续命，也不是运行时计时器。

## 最小示例

下面的函数返回两个输入切片中较长的一个。返回值可能来自 `x`，也可能来自 `y`，因此必须说明它至少和二者中较短的那段共同有效：

```rust
fn longer<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() >= y.len() {
        x
    } else {
        y
    }
}

let left = String::from("rust");
let result;
{
    let right = String::from("language");
    result = longer(&left, &right);
    println!("{result}");
}
```

`'a` 是一个生命周期参数名。它约束了输入引用和输出引用的关系，但不会让 `right` 在作用域外继续存在。

## 生命周期省略

很多函数不需要显式写生命周期，因为编译器可以使用省略规则推断：

```rust
fn identity(text: &str) -> &str {
    text
}
```

常用的省略规则可以概括为：

1. 每个引用参数先获得一个独立的生命周期。
2. 只有一个输入生命周期时，输出引用使用它。
3. 方法存在 `&self` 或 `&mut self` 时，输出引用通常使用 `self` 的生命周期。

当输入有多个引用，且返回值可能来自不同输入时，编译器无法替你猜测，就需要显式标注。

## 带引用的结构体

结构体如果保存引用，必须声明生命周期参数：

```rust
struct Label<'a> {
    text: &'a str,
}

let source = String::from("rust");
let label = Label { text: &source };
println!("{}", label.text);
```

`Label<'a>` 不能比 `source` 活得更久。若不希望结构体携带生命周期，可以让它拥有数据，例如保存 `String` 而不是 `&str`。

## 生命周期与所有权的选择

设计 API 时通常有三种选择：

- 函数只需要读取数据：接收 `&str`、`&[T]` 等借用。
- 函数需要保存数据：让结构体拥有 `String`、`Vec<T>` 等值。
- 函数返回输入的一部分：使用生命周期标注表达返回值和输入的关系。

不要为了“少写生命周期”而随意 `clone`，也不要为了“零拷贝”让所有结构体都保存引用。拥有数据通常更容易维护。

## `'static` 的边界

`'static` 表示引用在整个程序运行期间都有效。字符串字面量是典型的 `&'static str`：

```rust
let name: &'static str = "rust";
```

`'static` 也可能出现在泛型约束中，表示某个值不包含短生命周期借用。它不等于“必须放在全局变量里”，也不应该作为不理解生命周期时的万能修复。

## 编译器视角

- `E0106`：返回引用但缺少生命周期标注。检查返回值可能来自哪个输入。
- `E0515`：返回了局部变量的引用。局部变量离开函数后已失效，应该返回拥有的数据或借用输入。
- `E0597`：借用值活得不够久。扩大 owner 的作用域，或调整结构体/函数的所有权设计。

生命周期错误的核心问题通常是“数据应该由谁拥有”，而不只是少了一个 `'a`。

## 常见误区

- 生命周期标注不会延长任何值的实际存活时间。
- `T: 'a` 表示 `T` 内部的借用至少活到 `'a`，不表示 `T` 本身一定是引用。
- `&'static str` 和 `String` 的所有权模型不同，不能混为一谈。
- 如果一个结构体长期保存引用很复杂，可以考虑让它拥有数据，或使用更高层的共享所有权结构。
