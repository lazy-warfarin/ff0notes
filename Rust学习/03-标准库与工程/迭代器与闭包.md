# 迭代器与闭包

## 要解决的问题

迭代器把“如何遍历”与“如何处理元素”拆开；闭包则把短小的行为作为值传递。二者组合后，可以用清晰的流水线表达转换、过滤、聚合和错误传播。

这不是为了把所有循环改成链式调用，而是为了明确数据流、所有权和终止条件。

## 闭包捕获

```rust
let limit = 10;
let is_small = |value: &i32| *value < limit;

println!("{}", is_small(&7));
```

闭包会根据使用方式自动捕获外部变量：

- 借用读取：类似 `Fn`。
- 可变借用：类似 `FnMut`。
- 获取所有权：类似 `FnOnce`。

需要在线程或更长生命周期中保存闭包时，显式使用 `move`：

```rust
let prefix = String::from("rust");
let make_label = move |name: &str| format!("{prefix}: {name}");

println!("{}", make_label("book"));
```

`move` 会让闭包取得捕获变量的所有权，但不代表闭包内部的所有值都变成 `'static`。

## 创建迭代器

对 `Vec<T>` 而言，三个常用入口的所有权含义不同：

```rust
let mut values = vec![1, 2, 3];

for value in values.iter() {
    println!("{value}"); // &i32
}

for value in values.iter_mut() {
    *value += 1; // &mut i32
}

for value in values.into_iter() {
    println!("{value}"); // i32，values 被消费
}
```

- `iter()`：产生不可变引用，不消费容器。
- `iter_mut()`：产生可变引用，不消费容器。
- `into_iter()`：按元素取得所有权，通常会消费容器。

写接口时，优先根据所有权需求选择入口，而不是依赖编译器帮你猜。

## 适配器是惰性的

`map`、`filter`、`take` 等方法只构造新的迭代器，直到调用终止操作才真正执行：

```rust
let result: Vec<i32> = (1..=6)
    .map(|value| value * value)
    .filter(|value| value % 2 == 0)
    .collect();

assert_eq!(result, vec![4, 16, 36]);
```

常见终止操作包括：

- `collect`
- `sum`、`product`
- `count`
- `find`、`any`、`all`
- `fold`

链式调用中的每一步都应该有清晰的数据类型和所有权含义。

## `collect` 的类型提示

`collect` 可以收集成多种容器，因此经常需要类型标注：

```rust
fn parse_numbers(input: &str) -> Result<Vec<i32>, std::num::ParseIntError> {
    input
        .split_whitespace()
        .map(str::parse::<i32>)
        .collect::<Result<Vec<_>, _>>()
}
```

这个例子利用 `Result` 的迭代器实现：只要其中一次解析失败，整个收集就失败；全部成功时得到 `Vec<i32>`。

## `fold` 与状态

```rust
let sum = [1, 2, 3, 4].into_iter().fold(0, |total, value| {
    total + value
});

assert_eq!(sum, 10);
```

`fold` 适合把每个元素汇总到一个累积状态中。若逻辑包含多个相互依赖的状态，普通 `for` 循环可能更易读，不必强行压缩成一条链。

## 自定义迭代器与关联类型

```rust
struct Counter {
    current: u8,
}

impl Iterator for Counter {
    type Item = u8;

    fn next(&mut self) -> Option<Self::Item> {
        if self.current < 3 {
            let value = self.current;
            self.current += 1;
            Some(value)
        } else {
            None
        }
    }
}
```

这里的 `type Item` 是 [[Rust学习/02-类型系统/泛型与Trait|泛型与 Trait]] 中介绍的关联类型。迭代器通过返回 `None` 表示遍历结束。

## 编译器视角

- 闭包捕获方式由其使用方式决定；需要修改外部值时，闭包通常实现 `FnMut`。
- 迭代器适配器通常借用或消费上游迭代器，链条中的每一步都可能改变所有权。
- 借用容器生成迭代器后，不能在借用仍然使用时修改或移动容器。
- `collect` 报错时，先写出完整目标类型，再逐步删减标注。

## 常见误区

- 忘记迭代器是惰性的，以为调用 `map` 就已经执行。
- 混淆 `iter()` 和 `into_iter()`，导致 move 或借用错误。
- 为了“函数式”而写出过长链条，反而隐藏边界条件。
- 在闭包中隐式捕获大量状态，导致生命周期或可变借用冲突。
- 用 `collect::<Vec<_>>()` 掩盖了本应传播的 `Result`。
