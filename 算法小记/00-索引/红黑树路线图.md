# 红黑树路线图

目标：用 Rust 从零实现普通红黑树。**先完成不允许重复键的基础 `RbTree`，再扩展为 `RbMultiset`，然后加入顺序统计和自定义子树信息。** 这里记录学习顺序，不替代代码仓库，也不预先标记任何题已通过。

- 知识点：[[02-数据结构/树/01-红黑树|红黑树原理与 Rust 实现设计]]
- 题单：[[05-题单/Codeforces/红黑树题单|Codeforces 红黑树题单]]
- 状态：[[00-索引/题目状态看板|题目状态看板]]

> [!note] 选题口径
> 练习的是红黑树能提供的接口，不是宣称这些题只能用红黑树。先让基础树通过本地自检，不为了尽早套习题就加入排名功能；有序集合习题排在顺序统计习题之前，紧内存挑战不作为第一版的入门验收。

## 0. 先备知识与基础表示

- [ ] 理解 BST 的中序有序性及五条红黑性质，能解释黑高为什么保证对数树高。
- [ ] 先读 [[02-数据结构/树/01-红黑树#视频导读：从 2-3-4 树到红黑树|视频导读：从 2-3-4 树理解红黑编码]]：能把黑结点与直接红孩子收缩成大结点，说明黑高、分裂、借与并的意义。
- [ ] 能区分“父红叔红的满结点分裂”与“父红叔黑的三键重排”；双红并不总是容量溢出。
- [ ] 选择普通红黑树，不混入 LLRB 修复规则。
- [ ] 第一版命名为 `RbTree`，采用 `Vec<Node> + 下标`，以 `0` 为共享黑色 `NIL`。
- [ ] 结点先只保留键、父、左孩子、右孩子和颜色；树中另存 `root` 与全树 `len`，不要求 `cnt`、`size`、`pull`、排名或第 $k$ 小。
- [ ] 明确有序集合语义：重复插入忽略，删除不存在键不改变树，只有成功插入 / 删除才改变 `len`。

## 1. 基础 `RbTree`：查找、旋转与插入

- [ ] 写 BST 查找、中序遍历、最小 / 最大值、前驱后继和边界查询。
- [ ] 写左右旋，检查整树根、父子指针及中序顺序，不维护尚未加入的子树信息。
- [ ] 写插入修复，覆盖叔叔红、内侧与外侧，以及镜像情况；内侧旋转先按笔记重定位当前结点。
- [ ] 每次完整操作后检查 BST、全树 `len`、根颜色、红红冲突和黑高，与 `BTreeSet` 或排序去重后的 `Vec` 对拍。

本阶段先用本地专项序列验收，不要求为了完成某道排名题提前加入增广功能。

## 2. 基础 `RbTree`：删除与有序集合练习

- [ ] 实现 `remove`：查找目标、必要时搬后继的键，再摘除真实结点；第一版没有重数分支。
- [ ] 保存真正摘除结点的原颜色，覆盖黑兄弟 / 红兄弟与近侄 / 远侄情况，并完成镜像分支。
- [ ] `NIL` 替代位置显式保留父和左右侧，不依赖共享哨兵的父指针。
- [ ] 检查反复删根、删最小 / 最大、删到空、删不存在键、重复插入同键及后继接回等情况。
- [ ] 与 `BTreeSet` 对拍插入 / 删除返回值、查找、前驱后继、中序遍历和 `len`。

基础版练习：[[04-题库/Codeforces/1690G-Count-the-Trains|1690G Count the Trains]]。

这道题不需要重数或排名查询，能衔接基础树的插入、删除、前驱后继与长度接口；业务逻辑仍需单独证明多次删除的总次数界，不能把整次消息都误写成最坏对数时间。

## 3. 扩展 `RbMultiset`，再加入顺序统计

- [ ] 基础树稳定后增加 `cnt`，实现重复插入、`count` 与 `remove_one`；把全树 `len` 调整为计重总数。
- [ ] 多重集合删除时，区分减一次重数与摘除结点；双孩子删除须完整搬移后继的键和重数。
- [ ] 再加入 `size` 与 `pull`，补齐纯重数变化、旋转和删除后的祖先信息更新。
- [ ] 实现 `rank`、`upper_rank`、1-based `kth`，用保留重复值的排序 `Vec` 或 `BTreeMap` 对拍。
- [ ] 追加重数、子树大小、非法排名与后继多重数的检查，不把这些要求追溯到基础版。

顺序统计练习：[[04-题库/Codeforces/1579E2-Array-Optimization-by-Deque|1579E2 Array Optimization by Deque]]。

这一题只使用扩展版的插入和排名查询；“本题不需要删除”不意味着基础树必须等到这里才学习删除。学习顺序按实现依赖安排，不按题目 rating 排序。

## 4. 第 $k$ 小删除与紧内存挑战（可选）

- [ ] 本地把 `insert`、`remove_one`、`kth`、重数与根 `size` 混合对拍。
- [ ] 若要提交紧内存题，先测 `size_of::<Node>()` 和峰值内存，再考虑窄索引、受控容量、槽位复用与输入缓冲。

专项练习：[[04-题库/Codeforces/1354D-Multiset|1354D Multiset]]。

> [!warning] 1354D 不是宽松的红黑树模板题
> 官方内存限制为 28 MB，初始元素数和查询数都可达 $10^6$。它适合检验第 $k$ 小删除的语义，但教学版 `usize` 结点池或逐元素分配未必能通过；若只想高效过题，有界值域树状数组通常更省空间。具体预算见题卡。

## 5. 自定义增广信息

- [ ] 用左右子树和当前键推导 `pull`，明确局部排名与全局排名的偏移。
- [ ] 每次旋转、插入、删除后同时检查 `size` 与聚合字段。
- [ ] 对拍空集、短集合、删除后所有后继排名平移，以及超出 32 位的累加值。

挑战练习：[[04-题库/Codeforces/85D-Sum-of-Medians|85D Sum of Medians]]。

这道题键互异，可以在基础 `RbTree` 上直接增加 `size` 和分类聚合，不必为了复用多重集合版本而保留 `cnt`。多重集合与信息增广是可独立选择的扩展，紧内存题也不是进入本阶段的强制前置。

## 完成标准

- [ ] 基础版先跑结构与红黑性质检查、集合接口对拍，再用有序集合题检验可观察行为。
- [ ] 多重集合、顺序统计、自定义增广逐层实现，只检查当前已经引入的字段和接口。
- [ ] 实现留在 Rust 代码仓库；实际完成后再回填题卡 `code_path`、状态和复盘，并同步看板。
