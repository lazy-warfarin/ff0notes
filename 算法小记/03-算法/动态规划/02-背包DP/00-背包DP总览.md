## 适用场景

题目通常给出若干物品、一个或多个容量（重量、金额、时间、bug 数等）以及每件物品的收益，要求在容量限制下：

- 求最大值或最小值；
- 判断某个容量是否可达；
- 统计满足条件的方案数。

判断是不是背包，先问三个问题：

1. 每件物品能选几次：一次、无限次，还是有上限？
2. 资源约束是一个维度还是多个维度？
3. 统计的是组合、排列，还是只求最优值/可行性？

## 核心思想

背包 DP 的本质是按物品或物品组逐个决策。设物品 `i` 的重量为 `w_i`、价值为 `v_i`，容量上限为 `C`。

统一的二维状态可以写成：

```text
f[i][j] = 处理前 i 类物品，容量为 j 时的答案
```

不同题目的区别集中在两处：

- 当前物品能选择多少个；
- 转移时能否读取已经包含当前物品的状态。

这两点决定了转移方程和容量循环方向。

状态合并方式取决于目标：

| 目标 | 状态含义 | 合并方式 |
| --- | --- | --- |
| 最大值 | 最大价值/收益 | `max` |
| 最小值 | 最小代价/件数 | `min` |
| 可行性 | 是否存在方案 | `or` |
| 计数 | 方案数 | `+`（通常取模） |

## 状态定义

最通用的转移是在当前物品或当前组上枚举选择量：

$$
f_i[j]=
\operatorname{op}_{k\in K_i(j)}
\left(f_{i-1}[j-k w_i]+k v_i\right)
$$

其中 `K_i(j)` 由物品规则决定：

| 类型 | 可选件数 `k` |
| --- | --- |
| 01 背包 | `0` 或 `1` |
| 完全背包 | `0 <= k <= floor(j / w_i)` |
| 多重背包 | `0 <= k <= min(c_i, floor(j / w_i))` |
| 分组背包 | 从当前组中选一个物品，或整组不选 |

依赖背包需要先保证主件被选择，再把合法组合当作分组选择。计数和方案还原还需要额外规定“不同顺序是否算不同方案”。

## 转移方程

01 和完全背包是最常用的基础模型：

- 01 背包容量倒序，因为当前物品最多使用一次；
- 完全背包容量正序，因为允许继续使用当前物品。

```text
// 01 背包
for each item (w, v):
    for j from C down to w:
        dp[j] = op(dp[j], dp[j - w] + v)

// 完全背包
for each item (w, v):
    for j from w to C:
        dp[j] = op(dp[j], dp[j - w] + v)
```

## 初始化与边界

### 最值型

- 最大值：不可达状态初始化为负无穷；
- 最小值：不可达状态初始化为正无穷；
- 对“最大价值且不要求装满”的 01 背包，通常可以令所有 `dp[j] = 0`；
- “恰好容量”只能令 `dp[0] = 0` 可达，其余为不可达。

### 可行性型

```text
dp[0] = true
其余 dp[j] = false
```

### 计数型

```text
dp[0] = 1
其余 dp[j] = 0
```

`dp[0] = 1` 表示空方案。答案位置必须与状态定义一致：

- 恰好容量 `C`：取 `dp[C]`；
- 不超过容量 `C` 的最值：通常取 `max(dp[0..=C])`；
- 不超过容量 `C` 的计数：通常求 `sum(dp[0..=C])`；
- 至少达到某容量：根据状态定义取对应区间，或改用剩余容量建模。

## 遍历顺序

核心判断方法是：看转移右侧是否允许使用“当前物品已经更新过的状态”。

- 允许重复使用当前物品：容量正序；
- 不允许重复使用：容量倒序；
- 分组中每组最多选一个：整组读取上一组状态；
- 计数中顺序不重要：物品放在外层；
- 计数中顺序重要：容量放在外层。

具体实现顺序见各分支页面。

## 空间优化

二维状态 `f[i][j]` 如果只依赖上一层，可以压缩成 `dp[j]`：

- 01 背包通过容量倒序模拟上一层；
- 完全背包通过容量正序继续使用当前物品；
- 分组背包建议保留 `prev` 和 `cur`，避免同组状态污染；
- 需要方案还原时，额外记录前驱物品、前驱容量或选择数量。

空间复杂度通常从 `O(nC)` 降为 `O(C)`；二维费用背包从 `O(nXY)` 降为 `O(XY)`。

## 复杂度

设物品数为 `n`、容量为 `C`：

| 类型 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| 01 背包 | `O(nC)` | `O(C)` |
| 完全背包 | `O(nC)` | `O(C)` |
| 多重背包朴素枚举 | `O(nC max_count)` | `O(C)` |
| 多重背包二进制拆分 | `O(nC log max_count)` | `O(C)` |
| 分组背包 | `O(C * 组内物品总数)` | `O(C)` 或 `O(2C)` |
| 二维费用背包 | `O(nXY)` | `O(XY)` |

## 常见错误

- 把 01 背包容量写成正序，导致同一物品被重复使用。
- 把完全背包容量写成倒序，结果退化成 01 背包。
- 把“恰好容量”的不可达状态初始化为 `0`。
- 求“不超过容量”的方案数时只取 `dp[C]`。
- 方案数很大却没有取模，或使用了不够大的整数类型。
- 只盯着某个变体的模板，没有先判断物品可选次数和资源维度。
