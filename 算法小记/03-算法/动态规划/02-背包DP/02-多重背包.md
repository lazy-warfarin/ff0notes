# 多重背包

返回 [[03-算法/动态规划/02-背包DP/00-背包DP总览|背包 DP 总览]]。

## 适用场景

每类物品最多选择固定件数 `c_i`，而不是只选一次或无限次使用。

典型关键词是“第 `i` 种物品有 `s_i` 件”“每类物品最多取 `c_i` 个”。

## 核心思想

多重背包把 01 背包的“选或不选”扩展成“选择 `0` 到 `c_i` 件”。

可以先写二维转移，再根据是否要求方案数选择实现方式：

- 最值或可行性：朴素枚举、二进制拆分、单调队列；
- 计数：按容量模重量做滑动窗口，不能直接套普通二进制拆分。

## 状态定义

设 `f_i[j]` 表示处理前 `i` 类物品、容量为 `j` 时的答案。第 `i` 类物品重量为 `w_i`、价值为 `v_i`、最多选 `c_i` 件：

$$
f_i[j]=
\operatorname{op}_{0\le k\le \min(c_i,\lfloor j/w_i\rfloor)}
\left(f_{i-1}[j-k w_i]+k v_i\right)
$$

计数型去掉价值项，只累加上一层的方案数。

## 转移方程

### 朴素枚举

```text
for each item type (w, v, count):
    for j from C down to 0:
        for k from 1 to min(count, j / w):
            dp[j] = op(dp[j], prev[j - k * w] + k * v)
```

复杂度为 `O(n C max_count)`，适合件数较小的情况。

### 二进制拆分

把 `c` 件拆成若干组，每组按 01 物品处理：

```text
parts = []
k = 1
while k < count:
    parts.push((k * w, k * v))
    count -= k
    k *= 2
if count > 0:
    parts.push((count * w, count * v))
```

每组最多选一次，适用于最值和可行性，复杂度约为 `O(n C log max_count)`。

### 单调队列

按 `j = r + q w` 分组，大容量的最值型转移可以维护

$$
f_i[r+qw]
=
qv+
\max_{\max(0,q-c_i)\le t\le q}
\left(f_{i-1}[r+tw]-tv\right)
$$

单类物品的转移可以降到 `O(C)`。

### 方案数

计数时不要直接使用普通二进制拆分：不同拆分组可能重复表示同一个件数选择。

按容量模 `w` 分组，用滑动窗口累加：

$$
f_i[r+qw]
=
\sum_{t=\max(0,q-c_i)}^q f_{i-1}[r+tw]
$$

## 初始化与边界

- 最大值且不要求装满：通常令所有状态为 `0`；
- 恰好容量或最小值：只让 `dp[0]` 可达，其余按目标设为不可达值；
- 可行性：`dp[0] = true`；
- 计数：`dp[0] = 1`，表示空方案；
- 使用 `prev` 时，必须先准备完整的上一层状态，不能边枚举边覆盖。

## 遍历顺序

| 实现方式 | 典型顺序 | 关键点 |
| --- | --- | --- |
| 朴素枚举 | 物品 -> 容量倒序 -> 件数 | 件数读取上一层 |
| 二进制拆分 | 拆分组 -> 容量倒序 | 每组最多选一次 |
| 单调队列 | 按容量模 `w` 分组 | 维护 `f - t v` |
| 计数滑窗 | 按容量模 `w` 分组 | 窗口内累加方案数 |

## 空间优化

朴素枚举和二进制拆分都可以压缩到 `O(C)`。单调队列通常需要两个长度为 `C + 1` 的数组轮换，空间仍为 `O(C)`。

若需要还原每类物品选了多少件，还要保存选择数量或前驱状态。

## 复杂度

| 类型 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| 朴素枚举 | `O(n C max_count)` | `O(C)` |
| 二进制拆分 | `O(n C log max_count)` | `O(C)` |
| 单调队列 | `O(nC)` | `O(C)` |

## 常见错误

- 枚举件数时读取了当前物品已经更新过的状态。
- 二进制拆分后仍把它当成可以重复选择的物品。
- 计数型直接套普通二进制拆分，导致同一选择被重复计数。
- 恰好容量与不超过容量的初始化混用。
