# 多维与依赖背包

返回 [[03-算法/动态规划/02-背包DP/00-背包DP总览|背包 DP 总览]]。

## 适用场景

- 每件物品同时消耗两个或多个资源，例如重量与体积、时间与预算；
- 选择附件前必须先选择主件；但依赖也可能是优惠券、权限等前置条件（815C 属于优惠券依赖，商品本身可以全价购买而不买父件）；
- 依赖关系形成一棵树，子树的选择需要合并到父节点。

判断是否是多维背包，看每件物品是否用一组费用向量而不是单个容量来描述。

## 核心思想

多维费用背包只是把容量维度从一维扩展到二维或更高维。每一维仍然遵循同一套方向规则：01 物品的所有费用维度都倒序，允许重复使用时都正序。

依赖背包的关键是保证“选了附件就选了主件”。主件加少量附件时，可以先把合法组合枚举出来，再退化成分组背包；依赖形成一般树时，使用树形 DP 合并子树。

## 状态定义

二维费用背包设第一维费用上限为 `X`、第二维费用上限为 `Y`：

$$
dp[x][y]=
\text{处理到当前物品，两类费用分别为 }x,y\text{ 时的最优答案}
$$

一般多维状态写成 `dp[c_1][c_2]...[c_d]`。若物品 `i` 的费用向量为 `(w_i, c_i, ...)`，状态维数与费用向量维数相同。

树形依赖可以使用 `dp[u][j]` 表示在以 `u` 为根的子树中选择物品、容量为 `j` 时的最优答案。若必须先选父节点，初始化时应从选择 `u` 本身开始。

## 转移方程

### 二维 01 背包

$$
dp[x][y]=
\operatorname{op}\left(
dp[x][y],\
dp[x-w_i][y-c_i]+v_i
\right)
$$

两个费用维度都要倒序：

```text
for each item:
    for x from X down to w:
        for y from Y down to c:
            dp[x][y] = op(dp[x][y], dp[x - w][y - c] + v)
```

### 二维完全背包

两个费用维度都改为正序：

```text
for each item:
    for x from w to X:
        for y from c to Y:
            dp[x][y] = op(dp[x][y], dp[x - w][y - c] + v)
```

若不同物品的使用次数不同，按物品类型分别选择循环方向，不能只检查其中一维。

### 主件与附件依赖

主件带两个附件时，先枚举该组所有合法组合：

```text
只选主件
主件 + 附件 1
主件 + 附件 2
主件 + 附件 1 + 附件 2
```

把每个合法组合看成一个 `(weight, value)` 选项，然后按分组背包合并：

$$
f_i[j]=
\max\left(
f_{i-1}[j],\
\max_{(w,v)\in G_i,\ w\le j}
\{f_{i-1}[j-w]+v\}
\right)
$$

对应伪代码：

```text
for each main-item group:
    cur = prev
    for capacity j from 0 to C:
        for legal combination (w, v):
            if j >= w:
                cur[j] = max(cur[j], prev[j - w] + v)
    prev = cur
```

### 一般树形依赖

1. 按后序处理节点，先完成所有子节点；
2. 令 `dp[u][w_u] = value_u`，表示必须选择 `u`；
3. 依次把每个子节点 `v` 的合法状态合并到 `u`；
4. 合并时枚举分给子树的容量，并保证父节点已经被选择。

若根节点只是虚拟起点，可以增加一个不消耗资源的虚拟根，把若干依赖树连接起来。

## 初始化与边界

- 二维背包的 `dp[0][0] = 0` 表示两类费用都未使用的空方案；其余状态按恰好费用或不超过费用设置。
- 若第一维使用“不超过”的语义，可以为该维所有容量预置 `0`，但另一维仍必须保持相同的状态语义。
- 依赖背包必须在每个合法组合中包含主件，不能允许单独选择附件。
- 树形依赖若要求父节点必选，未选择父节点的状态应设为不可达。

## 遍历顺序

| 类型 | 典型循环方向 | 原因 |
| --- | --- | --- |
| 二维 01 背包 | 两个费用维度都倒序 | 防止物品重复使用 |
| 二维完全背包 | 两个费用维度都正序 | 允许重复使用当前物品 |
| 主件附件分组 | 组 -> 容量 -> 合法组合，统一从 `prev` 读取 | 每组至多选择一个合法组合 |
| 树形依赖 | 后序合并子树 | 父节点依赖子节点状态 |

## 空间优化

二维费用背包从 `O(nXY)` 压缩到 `O(XY)`。树形依赖通常为每个节点保留 `O(C)` 状态，若只保留当前子树的结果，总空间为 `O(nC)`。

需要还原具体选择时，不能只保留压缩后的最值数组，还要记录每个状态对应的选择或前驱。

## 复杂度

| 类型 | 时间复杂度 | 空间复杂度 |
| --- | --- | --- |
| 二维费用背包 | `O(nXY)` | `O(XY)` |
| 主件附件分组 | `O(C * 合法组合总数)` | `O(C)` 或 `O(2C)` |
| 朴素树形依赖合并 | 通常不超过 `O(nC^2)` | `O(nC)` |

## 常见错误

- 二维 01 背包只倒序了一个费用维度。
- 把不同物品类型的循环方向混在一起。
- 依赖组合中允许单独选择附件。
- 树形合并前没有先选中父节点。
- 只优化了最值，却忘记为方案还原保留前驱。
