# 质数判定与筛法

## 适用场景

- 少量整数只需判断是否为质数：试除法。
- 需要 $[0,N]$ 内所有质数，或大量查询某个有界整数是否为质数：埃氏筛。
- 大量有界整数需要质因数分解：线性筛生成最小质因子表 SPF。
- 固定上限、不希望程序运行时执行筛法：先理解本篇，再看 [[03-算法/数论/04-编译期质数生成|编译期质数生成]]。

## 核心思想

### 单个数的判定

若 $n\ge2$ 是合数，则存在不超过 $\sqrt n$ 的质因子。只要发现一个非平凡因子即可判为合数；否则是质数。$0$ 和 $1$ 都不是质数。

```rust
fn is_prime(n: u64) -> bool {
    if n < 2 {
        return false;
    }
    if n % 2 == 0 {
        return n == 2;
    }
    let mut d = 3_u64;
    while d <= n / d {
        if n % d == 0 {
            return false;
        }
        d += 2;
    }
    true
}
```

### 埃拉托斯特尼筛（埃氏筛）

先把 $[2,N]$ 标为可能是质数。每发现一个质数 $p$，划掉它的倍数，从 $p^2$ 开始：

$$
p^2,\ p^2+p,\ p^2+2p,\ldots
$$

为什么不从 $2p$ 开始？小于 $p^2$ 的合数倍数 $kp$（$2\le k<p$）已有小于 $p$ 的质因子，之前已经被划掉。

### 线性筛（欧拉筛）与 SPF

令 $\operatorname{spf}(x)$ 为 $x\ge2$ 的最小质因子。遍历到 $x$ 时，只用不大于 $\operatorname{spf}(x)$ 的质数 $p$ 生成合数 $xp$，并令：

$$
\operatorname{spf}(xp)=p.
$$

当 $p=\operatorname{spf}(x)$ 后停止内层枚举，保证每个合数只由它的最小质因子生成一次。

## 状态定义

- 埃氏筛：`prime[x]` 表示 $x$ 是否仍被标记为质数。
- 线性筛：`spf[x]` 为最小质因子，未赋值时为 $0$；`primes` 按升序保存已发现的质数。
- `spf[0]`、`spf[1]` 保留为 $0$，没有最小质因子的含义。

## 转移方程

埃氏筛处理质数 $p$ 时，把所有 $p^2+kp\le N$ 的位置置为假。

线性筛处理 $x$ 时：

1. 若 `spf[x] == 0`，则 $x$ 为质数，令 `spf[x] = x` 并加入质数表。
2. 依次枚举质数 $p$，在 $xp\le N$ 时令 `spf[x * p] = p`。
3. 一旦 $p=\operatorname{spf}(x)$，立即结束内层循环。

唯一性解释：对任意合数 $y$，取 $p=\operatorname{spf}(y)$、$x=y/p$，有 $p\le\operatorname{spf}(x)$，因此一定能生成 $y$；若换一个更大的质因子生成，内层循环会在允许它之前停止。

已有 SPF 表后，分解时反复取出 $p=\operatorname{spf}(n)$，除去所有 $p$，再处理剩余部分。

## 初始化与边界

- 以下两种筛法的参数 `limit` 都是**包含的上界**，数组长度是 `limit + 1`；假设这个长度不溢出且内存足以分配。
- `limit` 为 $0$ 或 $1$ 时，质数表应为空，不能无条件访问下标 $1$。
- 埃氏筛计算 `p * p` 前，先用 `p <= limit / p` 保证平方不超过上界。
- 线性筛计算 `x * p` 前，先用 `p <= limit / x` 保证不溢出且下标有效。
- SPF 分解只接受 $1\le n\le N$；$1$ 返回空分解，$0$ 和超出表范围的输入不合法。

## 遍历顺序

### 埃氏筛：只需要质数标记时优先使用

```rust
fn sieve(limit: usize) -> Vec<bool> {
    let mut prime = vec![true; limit + 1];
    prime[0] = false;
    if limit >= 1 {
        prime[1] = false;
    }
    let mut p = 2_usize;
    while p <= limit / p {
        if prime[p] {
            for multiple in (p * p..=limit).step_by(p) {
                prime[multiple] = false;
            }
        }
        p += 1;
    }
    prime
}
```

筛完后，从小到大扫描所有为真的下标，就能得到有序质数表；单点判定则直接访问 `prime[x]`，先确保下标在表内。

### 线性筛：同时得到质数表与 SPF

```rust
fn linear_spf(limit: usize) -> (Vec<usize>, Vec<usize>) {
    let mut spf = vec![0; limit + 1];
    let mut primes = Vec::new();
    for x in 2..=limit {
        if spf[x] == 0 {
            spf[x] = x;
            primes.push(x);
        }
        for &p in &primes {
            if p > limit / x {
                break;
            }
            spf[x * p] = p;
            if p == spf[x] {
                break;
            }
        }
    }
    (primes, spf)
}

// spf 必须来自覆盖 n 的有效最小质因子表。
fn factorize_spf(mut n: usize, spf: &[usize]) -> Vec<(usize, u32)> {
    assert!(n >= 1 && n < spf.len());
    let mut factors = Vec::new();
    while n > 1 {
        let p = spf[n];
        let mut exponent = 0_u32;
        while n % p == 0 {
            n /= p;
            exponent += 1;
        }
        factors.push((p, exponent));
    }
    factors
}
```

例：`linear_spf(10)` 的质数表为 `[2, 3, 5, 7]`，且 `spf[8] == 2`、`spf[9] == 3`；传入该表后，`factorize_spf(8, &spf)` 得到 `[(2, 3)]`。

## 空间优化

- 只判断素性：保存布尔标记即可，不必额外保存所有 SPF。
- 需要反复分解：保存 SPF，用空间换查询时间；内存紧张且上界允许时，可考虑较窄的整数类型。
- 仅处理奇数可减少标记空间，但下标映射更容易写错，应先熟悉普通筛法。
- 若只查询很窄的区间 $[L,R]$，而 $R$ 很大，可考虑分段筛：先生成不超过 $\sqrt R$ 的质数，再划去区间内的倍数，并单独排除小于 $2$ 的数。它仍需要基础质数表，不能无条件省掉这部分开销。

## 复杂度

以下筛法复杂度按 $N\ge2$ 描述，$N<2$ 时直接得到空质数表：

- 单个数试除判定：时间 $O(\sqrt n)$，空间 $O(1)$。
- 埃氏筛：时间 $O(N\log\log N)$，空间 $O(N)$；筛完后的单次素性查询为 $O(1)$。
- 线性筛：时间 $O(N)$，空间 $O(N)$；SPF 分解单个 $n$ 的除法次数为 $O(\log n)$，输出空间与不同质因子数量有关。
- 不要只凭渐进复杂度断言线性筛总比埃氏筛快；常数、内存访问和具体任务也会影响耗时。

试除法即使使用 `u64`，对非常大的质数也可能超时；若要在整个 64 位范围高效判素，需要另学有明确适用范围与底数集合的 Miller–Rabin，而不是认为本模板足够快。

## 常见错误

- 未把 $0$、$1$ 排除，或上界很小时访问越界。
- 分不清“数组长度”和“包含的最大值”，漏筛上界或查表越界。
- 从 $p^2$ 开始筛，却在做平方前没有防溢出。
- 在线性筛中漏掉 `p == spf[x]` 后的 `break`，导致合数被重复生成，失去线性复杂度保证；不要据此断言这份实现最终得到的 SPF 必然错误。
- 对任意输入直接查 SPF，忘记它只覆盖预处理上界内的正整数。
- 只需要分解少量整数，却预筛到每个整数的完整上界；先按数据规模比较直接试除、筛质数后试除与 SPF，不把质因数分解等同于必须建质数表。
- 多次询问反复构造同一张筛表，或误把运行时预处理称为编译期生成。
