# 编译期质数生成

## 适用场景

- 质数表上限在编译前已知，程序运行后只需要查表，不希望再执行筛法。
- 希望用编译期断言检查固定表中的关键值，避免手抄质数表。
- 固定范围的质因子掩码、少量固定质数集合等；先看 [[03-算法/数论/03-质数判定与筛法|质数判定与筛法]] 理解筛法本身。

如果上界必须从输入读取，就不能把这个输入相关的上界直接交给编译期求值。可以用题目给定的固定最大上界生成表，再在输入时检查范围。

## 核心思想

### 先区分“什么时候生成”

1. **运行时预处理**：程序启动后执行筛法，之后每次询问查表；筛法仍属于运行时间。
2. **首次使用时初始化**：例如 Rust 的 `LazyLock`、`OnceLock`；只是推迟执行，仍属于运行时。
3. **编译期求值**：编译器执行受支持的常量表达式，将结果放进程序需要的常量数据；运行时不再执行那次筛法。
4. **构建期或离线生成**：构建脚本或外部程序生成源码、再编译；也能免去运行时筛法，但不是语言内的常量求值，且可能不适合只接收单文件的评测环境。

> [!important] 能在编译期调用，不等于每次调用都在编译期
> Rust 的 `const fn`、C++ 的 `constexpr` 函数表示“允许常量求值”；普通运行时调用并不因此必然变成编译期调用。Rust 要放进常量上下文，C++ 可以用 `constexpr` 变量接收，或使用 C++20 的 `consteval` 立即函数。

Rust 的常量和静态项初始化器均属于常量上下文；本文用 `static` 保存最终表，避免在普通局部变量初始化中构造大数组，并给查表提供固定存储位置。语义依据见 [Rust Reference：Constant evaluation](https://doc.rust-lang.org/reference/const_eval.html)。

## 状态定义

本篇统一使用**数组长度** `LEN`：

- 覆盖的整数为 $[0,\mathrm{LEN}-1]$，当 `LEN == 0` 时为空范围。
- 若要覆盖包含的上界 $N$，令 `LEN = N + 1`，并保证加法不溢出。
- `flags[x]` 表示 $x$ 是否为质数。
- `PRIME_COUNT` 为表内质数数量，`PRIMES` 为长度恰好等于这个数量的有序质数数组。

这和运行时筛法笔记的 `limit` 参数不同：那里传的是**包含的上界**，不是数组长度。

## 转移方程

数学上的转移仍是埃氏筛：当 $p$ 为质数，把 $p^2,p^2+p,\ldots$ 标为合数；只需要处理 $p^2<\mathrm{LEN}$ 的 $p$。

变化的是实现环境：Rust 常量求值示例使用固定长度数组、下标、`while` 和整数运算，不依赖 `Vec::push`、文件、网络或运行时输入。

生成精确长度的质数数组采用两步：先统计质数数量，再以该常量数量作为数组长度收集质数；不需要在返回类型中写 `LEN + 1` 等依赖泛型参数的算术表达式。

## 初始化与边界

- 长度为 $0$ 或 $1$ 时，必须先检查长度再访问下标。
- $0$、$1$ 标为非质数；$2$ 是最小质数。
- 计算平方前使用除法比较；递增倍数前确认下一次加法不超过有效上界。
- 表中的查询仍需检查输入范围，编译期生成不能免除运行时下标检查。
- 编译器对常量求值有资源限制；固定上界较小适合示例，大表可能显著拖慢编译，甚至触发求值限制。

## 遍历顺序

### Rust：`const fn` 与静态表

下面是一组可放在同一个 Rust 源文件中的定义。`PRIME_FLAGS` 的初始化在编译期求值；最终的 `IS_PRIME` 和 `PRIMES` 是供运行时访问的静态表。

```rust
const fn prime_flags<const LEN: usize>() -> [bool; LEN] {
    let mut flags = [true; LEN];
    if LEN > 0 {
        flags[0] = false;
    }
    if LEN > 1 {
        flags[1] = false;
    }
    let mut p = 2_usize;
    while p < LEN && p <= (LEN - 1) / p {
        if flags[p] {
            let mut multiple = p * p;
            while multiple < LEN {
                flags[multiple] = false;
                if (LEN - 1) - multiple < p {
                    break;
                }
                multiple += p;
            }
        }
        p += 1;
    }
    flags
}

const fn count_primes<const LEN: usize>(flags: &[bool; LEN]) -> usize {
    let mut count = 0;
    let mut x = 0;
    while x < LEN {
        if flags[x] {
            count += 1;
        }
        x += 1;
    }
    count
}

const fn collect_primes<const LEN: usize, const COUNT: usize>(
    flags: &[bool; LEN],
) -> [usize; COUNT] {
    let mut primes = [0; COUNT];
    let mut count = 0;
    let mut x = 0;
    while x < LEN {
        if flags[x] {
            primes[count] = x;
            count += 1;
        }
        x += 1;
    }
    assert!(count == COUNT);
    primes
}

const LIMIT: usize = 1_000;
const LEN: usize = LIMIT + 1;
const PRIME_FLAGS: [bool; LEN] = prime_flags::<LEN>();
const PRIME_COUNT: usize = count_primes(&PRIME_FLAGS);
static IS_PRIME: [bool; LEN] = PRIME_FLAGS;
static PRIMES: [usize; PRIME_COUNT] =
    collect_primes::<LEN, PRIME_COUNT>(&PRIME_FLAGS);

// 编译期断言；断言失败时编译报错。
const _: () = {
    assert!(!PRIME_FLAGS[0]);
    assert!(!PRIME_FLAGS[1]);
    assert!(PRIME_FLAGS[2]);
    assert!(!PRIME_FLAGS[49]);
    assert!(PRIME_FLAGS[997]);
    assert!(PRIME_COUNT == 168);
};
```

使用时，在确认 `x <= LIMIT` 后读 `IS_PRIME[x]`；遍历 `PRIMES.iter()` 得到 $[2,3,5,\ldots,997]$。程序不需要重新筛，但遍历、查表和输入输出依然是运行时操作。

注意：`let flags = prime_flags::<1001>();` 是普通局部变量初始化，仅把函数声明成 `const fn` 不构成强制编译期求值的保证；不要把优化器可能做的常量折叠当成语言保证。

### C++20：`consteval` 与 `constexpr` 表

```cpp
#include <array>
#include <cstddef>

template <std::size_t LEN>
consteval std::array<bool, LEN> prime_flags() {
    std::array<bool, LEN> flags{};
    for (std::size_t x = 2; x < LEN; ++x) {
        flags[x] = true;
    }
    for (std::size_t p = 2; p < LEN && p <= (LEN - 1) / p; ++p) {
        if (!flags[p]) continue;
        for (std::size_t multiple = p * p; multiple < LEN;) {
            flags[multiple] = false;
            if ((LEN - 1) - multiple < p) break;
            multiple += p;
        }
    }
    return flags;
}

constexpr std::size_t LIMIT = 1'000;
constexpr auto IS_PRIME = prime_flags<LIMIT + 1>();
static_assert(!IS_PRIME[0] && !IS_PRIME[1]);
static_assert(IS_PRIME[2] && !IS_PRIME[49] && IS_PRIME[997]);
static_assert(prime_flags<0>().size() == 0);
static_assert(!prime_flags<1>()[0]);
```

- `consteval` 要求这里的调用通过常量求值完成，不能传入运行时读取的上界。
- 如评测环境只有 C++17，将函数上的 `consteval` 换成 `constexpr`；保留接收结果的 `constexpr auto IS_PRIME`，该初始化仍要求常量表达式。
- 仅写普通 `const auto table = 某个普通函数();`，不表示初始化发生在编译期；全局对象也可能进行运行时动态初始化。

相关声明规则见 [C++ 工作草案：constexpr 与 consteval](https://eel.is/c++draft/dcl.constexpr)。

## 空间优化

- 只查素性时，只保留 `IS_PRIME`；只需依次试除质数时，可以只保留质数数组作为最终使用的数据。
- 编译期生成只是把筛表计算从运行阶段移到编译阶段，不会让表的存储消失；还应考虑二进制大小和运行时内存。
- 若表很大，运行时筛一次常常比很重的编译期求值更实用。选择依据是范围、查询次数、编译限制与内存，而不是“编译期一定更快”。
- 需要先给 `LEN` 定个量级时，用 $\pi(x)$ 的界估算，见 [[03-算法/数论/05-质数计数与表长估计|质数计数与表长估计]]；但最终长度仍应由 `count_primes` 精确给出。

## 复杂度

设覆盖的包含上界为 $N\ge2$，质数个数为 $\pi(N)$：

- 算法层面，编译期筛表工作量为 $O(N\log\log N)$；统计和收集另需 $O(N)$，但编译器的实际常量求值耗时不等同于优化后的运行时筛法耗时。
- 保留标记表与质数表时，最终数据空间为 $O(N+\pi(N))$。
- 运行时单次素性查表为 $O(1)$，遍历整张质数表为 $O(\pi(N))$；不再有运行时筛表这一步。
- `const fn` 没有把原算法改成更低的渐进复杂度，只是改变求值阶段。

Rust 可能报告 `long_running_const_eval`；不要无检查地关闭限制或承诺固定的大上界必然可编译。该限制与编译器版本和具体实现有关，见 [Rust 官方说明](https://doc.rust-lang.org/stable/nightly-rustc/rustc_lint/builtin/static.LONG_RUNNING_CONST_EVAL.html)。

## 常见错误

- 把 `main` 开头的筛法、`LazyLock` 首次初始化或全局动态初始化称为“非运行期生成”。
- 只有 `const fn` / `constexpr` 函数声明，没有放进保证常量求值的上下文。
- 把运行时输入作为编译期数组长度，或混淆 `LEN` 与包含上界 $N$。
- 用 `Vec` 动态构造思路直接照搬到本文的固定数组常量求值实现。
- 认为编译期数据不占内存，或把“没有运行时筛表”误写成“整个功能没有运行时开销”。
