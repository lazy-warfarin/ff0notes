# 864E Fire

> [Codeforces 864E - Fire](https://codeforces.com/problemset/problem/864/E)

## 题意摘要

房子着火，共有 $n$ 件物品（$n \le 100$，$d_i \le 2000$）。抢救第 $i$ 件物品需要 $t_i$ 秒、价值 $p_i$；从时刻 $d_i$ 起该物品就被烧毁，因此必须在 $d_i$ 之前抢救完成（完成时刻严格小于 $d_i$）。一次只能抢救一件，求能带走的最大价值总和，并按抢救顺序输出物品编号。

## 识别信号

- "每件物品耗时 + 截止时间 + 最大价值和"是经典的排序后 01 背包。
- 题目要求输出具体方案，需要在背包转移时记录前驱。
- 截止条件是“从 $d_i$ 起烧毁”，所以完成时刻必须严格小于 $d_i$，转移写作 $j < d_i$，而不是 $j \le d_i$。

## 状态与转移

### 为什么按 $d_i$ 升序

先只看一个任意的可行抢救顺序。若相邻的两件物品 `a, b` 满足 `d_a > d_b`，设抢救到 `a` 之前已经用时 `C`。原来的完成时刻是

$$
c_a=C+t_a,\qquad c_b=C+t_a+t_b.
$$

交换为 `b, a` 后：

$$
c'_b=C+t_b<C+t_a+t_b=c_b<d_b,
$$

而

$$
c'_a=C+t_b+t_a=c_b<d_b<d_a.
$$

因此交换后两件物品仍然都能及时救出；两件物品之后的总用时不变，其他物品的完成时刻也不变。于是只要存在一对截止时间的逆序，就可以不断交换相邻逆序，最终得到一个按 $d_i$ 非降序排列的可行顺序。等截止时间的物品交换不受影响，可以任意排列。

这说明：**对于任意一个能救出的物品集合，若它本身可行，那么按截止时间升序抢救这个集合也一定可行。** 所以可以固定按 $d_i$ 升序做决策，不会漏掉任何最优集合。

### 背包 DP

排序时保留原编号。令 `dp[i][j]` 表示只考虑排序后的前 `i` 件物品、恰好用时 `j` 时的最大价值，`take[i][j]` 表示达到这个状态时是否选择第 `i` 件物品。$D = \max d_i$，只用考虑 $0 \le j < D$。

初始 `dp[0][0] = 0`，其余为 `-INF`。对第 `i` 件物品：

```text
for j from 0 to D - 1:
  dp[i][j] = dp[i - 1][j]       // 不救
  take[i][j] = false

  if j >= t[i] and j < d[i] and dp[i - 1][j - t[i]] != -INF:
    candidate = dp[i - 1][j - t[i]] + p[i]
    if candidate > dp[i][j]:
      dp[i][j] = candidate      // 救，完成时刻为 j
      take[i][j] = true
```

- 转移中的 `j < d[i]` 对应完成时间严格早于烧毁时刻；若 `t[i] >= d[i]`，可选区间为空，这件物品自然不会被选中。
- 因为已经按截止时间排序，`dp[i - 1][...]` 中的物品都在第 `i` 件之前抢救。
- 求答案时取 `max(dp[n][j])`。从 `(n, best_j)` 向前回溯：若 `take[i][j]` 为真，就把第 `i` 件加入答案并令 `j -= t[i]`，最后反转答案得到抢救顺序。

这里不要只用一个一维 `dp[j]` 配全局 `frm[j]` 还原。虽然倒序可以防止同一轮重复选择物品，但 `frm[j - t[i]]` 代表的旧状态可能在处理后续物品时被覆盖，导致回溯出排序在后面的物品。保留二维 `dp` 和 `take`，或者保存每个状态对应的历史版本，才能正确还原方案。

排序 + 01 背包见 [[03-算法/动态规划/02-背包DP/01-01背包与完全背包|01 背包与完全背包]]，方案还原见 [[03-算法/动态规划/02-背包DP/05-计数与方案|计数与方案]]。

## 复杂度

- 时间：$O(nD)$，其中 $D=\max d_i \le 2000$。
- 空间：$O(nD)$；本题最多约 `100 * 2000` 个状态。

## Rust 实现

- [examples/cf864e_fire/main.rs](file:///D:/projects/Rust/algorithm-notes/examples/cf864e_fire/main.rs)
- 按 $d_i$ 升序排序并保留原编号；`dp[i][j]` 表示前 `i` 件物品恰好用时 `j` 的最大价值。
- `take[i][j]` 只在“选择第 `i` 件物品”的候选值严格大于“不选”时记为 `true`，避免还原出总价值不符的方案。
- 已通过两组官方样例、首次 WA 的反例和 1000 组随机暴力对拍；Codeforces 提交 `395119810` 结果为 `OK`。

## 复盘

- 第一次错误：`take[i][j]` 记录成了“选择分支是否合法”，而不是“选择分支是否胜出”。这样第一行最大价值仍可能正确，但回溯出的方案可能是另一组价值更低的物品。
- 关键边界：完成时刻必须满足 $j < d_i$；答案应对所有 `dp[n][j]` 取最大值；回溯必须使用与二维 DP 同层的 `take[i][j]`。
- 一句话总结：按截止时间排序消除顺序不确定性，二维 01 背包负责选集合，`take` 只在严格改进时记录选择以保证方案还原正确。
