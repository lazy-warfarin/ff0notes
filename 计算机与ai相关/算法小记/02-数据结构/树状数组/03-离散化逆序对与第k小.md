# 离散化、逆序对与第 k 小

前置：[[01-树状数组基础|树状数组基础]]。本篇把树状数组的下标当成“值的排名”，维护每个值出现了多少次。

## 适用场景

- 值很大或包含负数，但只关心大小关系。
- 求逆序对，或统计历史元素中严格小于、严格大于某个值的数量。
- 维护一个多重集合，需要插入、删除一次出现、排名和第 $k$ 小。
- 所有可能插入的值已知，或值域本身较小，可以提前确定树状数组大小。

## 核心思想

### 1. 离散化保留大小关系

把所有可能出现的值排序、去重，得到：

$$
v_1<v_2<\cdots<v_m.
$$

将值 $v_i$ 映射为下标 $i$。例如原数组 $[100,-5,100,7]$ 的不同值为 $[-5,7,100]$，映射后是 $[3,1,3,2]$。

离散化保留**大小和相等关系**，不保留数值差距。相等的值必须映射到同一位置，不能把不同出现次数当作不同值排名。

若后面还有插入操作，要把未来可能插入的值也纳入离散化。无法预知新值的真正在线场景，可考虑平衡树或动态开点线段树。

### 2. 用频率前缀和统计排名

令 $c_i$ 为值 $v_i$ 的出现次数，BIT 维护 $c_i$。设当前共有 $t$ 个元素，当前值对应下标 $r$：

$$
\begin{aligned}
\#(\text{值}<v_r)&=\operatorname{prefix}(r-1),\\
\#(\text{值}\le v_r)&=\operatorname{prefix}(r),\\
\#(\text{值}>v_r)&=t-\operatorname{prefix}(r).
\end{aligned}
$$

这些计数都**包含重复元素的次数**。

### 3. 第 k 小是频率前缀和的下界查找

第 $k$ 小对应满足下面条件的最小下标 $p$：

$$
\operatorname{prefix}(p)\ge k.
$$

只要每个位置的频率非负，前缀和就单调不减，可以直接在树状数组上倍增查找。

## 状态定义

- `values`：排序去重后的原始值，Rust 中使用 0-based `Vec<i64>`。
- `r`：某个原始值在 BIT 中的 1-based 下标。
- `tree`：频率数组对应的树状数组，各块保存出现次数之和。
- $t$：已经插入、尚未删除的元素总数。
- `kth(k)`：返回第 $k$ 小所在的 **BIT 下标**，再用 `values[p - 1]` 还原原值。

逆序对按原序列位置定义：

$$
\#\{(i,j):i<j,\ a_i>a_j\}.
$$

排序只用于建立值与排名的对应关系，统计时仍按原序列顺序扫描。

## 转移方程

### 从左到右求逆序对

处理第 $j$ 个元素前，BIT 中只放位置小于 $j$ 的元素。当前已有 $j-1$ 个元素，当前值对应下标为 $r$，则新增逆序对数为：

$$
(j-1)-\operatorname{prefix}(r).
$$

先查询，再执行 `add(r, 1)`。查询包含相等值的前缀后，用总数减掉它们，剩下的才是严格更大的元素。

另一种写法是从右向左扫描，每步累加 `prefix_sum(r - 1)`，统计右侧严格更小的元素。

### 多重集合的操作

- 插入一个值：`add(r, 1)`。
- 删除一次出现：先保证该值频率大于 $0$，再 `add(r, -1)`。
- 按值统计排名：查询小于该值的元素个数；若需要它第一次出现的 1-based 名次，再加 $1$。
- 删除第 $k$ 小：先 `kth(k)` 找到下标，再对该下标执行 `add(p, -1)`。

### 查询值不在离散化数组中

查询阈值不要求提前收录。对任意阈值 $x$：

- `values.partition_point(|&v| v < x)` 得到小于 $x$ 的不同值个数，记作 $p$，答案为 `bit.prefix_sum(p)`。
- `values.partition_point(|&v| v <= x)` 得到小于等于 $x$ 的不同值个数，记作 $q$，答案为 `bit.prefix_sum(q)`。

注意这里的 $p,q$ 已经表示应查询的前缀长度，**不再加 $1$**。

## 初始化与边界

- 每组测试重新建立离散化数组，并清空频率 BIT。
- 普通数组下标从 $0$ 开始，而 BIT 下标为二分结果加 $1$。
- 逆序对要求严格大于，相等元素不计入。
- 逆序对上界为 $n(n-1)/2$，累加器至少使用合适的 64 位整数类型。
- 第 $k$ 小要求 $1\le k\le t$，非法排名返回 `None`。
- 删除操作可以传入 $-1$，但删除后每个位置的频率仍必须非负；下方 `kth` 不会逐点检查这一前提。

> [!warning] 普通求和与第 k 小的前提不同
> 基础树状数组可以维护带负数的数组。按前缀和找第 $k$ 小依赖前缀单调，因此只能用于各位置权重非负的情形；维护普通差分的 BIT 通常不满足这个条件。

## 遍历顺序

### 逆序对模板

下面代码复用基础篇的 `Fenwick`：

```rust
fn count_inversions(a: &[i64]) -> i64 {
    let mut values = a.to_vec();
    values.sort_unstable();
    values.dedup();

    let mut bit = Fenwick::new(values.len());
    let mut answer = 0_i64;
    for (seen, &x) in a.iter().enumerate() {
        let r = values.binary_search(&x).unwrap() + 1;
        answer += seen as i64 - bit.prefix_sum(r);
        bit.add(r, 1);
    }
    answer
}

impl Fenwick {
    // 前置条件：每个位置的频率均非负。
    // k 是 1-based 排名；返回值也是 1-based BIT 下标。
    fn kth(&self, mut k: i64) -> Option<usize> {
        if k <= 0 || k > self.prefix_sum(self.n) {
            return None;
        }

        let mut pos = 0;
        let mut step = 1;
        while step <= self.n / 2 {
            step <<= 1;
        }
        while step > 0 {
            let next = pos + step;
            if next <= self.n && self.tree[next] < k {
                k -= self.tree[next];
                pos = next;
            }
            step >>= 1;
        }
        Some(pos + 1)
    }
}
```

倍增从最大的 $2$ 的幂开始试跳。`pos` 表示已经跳过的前缀长度，`k` 表示扣除这个前缀后还要找的排名。当前候选块的频率总数小于 `k` 时，就能整块跳过，并扣掉它的频率；否则缩小步长继续找。

这里比较的是 `tree[next]`，并非重新调用一次 `prefix_sum(next)`。由于倍增的对齐关系，它恰好表示本轮准备跳过的那一块，所以整次查找只需 $O(\log m)$。

手算检查：

- $[3,1,2,2]$ 的逆序对数为 $3$，两个相等的 $2$ 不互相贡献逆序对。
- `values = [10, 20, 50]`、频率为 $[2,0,3]$ 时，第 $3$ 小位于 BIT 下标 $3$，原值为 `values[2] == 50`。
- 同一频率数组中，`kth(0)` 和 `kth(6)` 均返回 `None`。

## 空间优化

- BIT 按不同值数 $m$ 分配空间，不按原值的最大绝对值开数组。
- 原值本来就在较小正整数范围内时，可以直接把值当下标，省去排序和二分。
- 只求逆序对且不需要输出原值时，建好排名后可按需要释放中间数组；还要恢复第 $k$ 小原值时，应保留 `values`。

## 复杂度

- 离散化：排序时间 $O(n\log n)$，额外存储 $O(n)$。
- 逆序对：每个元素二分排名并查询、更新，整体时间 $O(n\log n)$；BIT 空间 $O(m)$。
- 已知下标时的插入、删除、排名查询：$O(\log m)$；倍增找第 $k$ 小：$O(\log m)$。
- 在值域上二分并反复查前缀和也能找第 $k$ 小，但会变成 $O(\log^2 m)$。

## 常见错误

- 离散化前忘记去重，让相等值占据不同排名。
- 为了离散化直接把原数组排序，丢掉逆序对的位置关系。
- 从左向右求逆序对时，用 `seen - prefix_sum(r - 1)`，把相等元素也算进去。
- 忘记先查询、再插入当前元素，使“历史元素”的语义混乱。
- 删除不存在的元素，频率变成负数后继续使用 `kth`。
- 倍增判断写成 `tree[next] <= k`；等于时已经到达目标，不能整块跳过。
- 把 `kth` 的返回下标当成原始值，或用 `values[p]` 还原导致偏移一位。
- 未来插入的值没有纳入离散化，却沿用旧排名直接插入。
