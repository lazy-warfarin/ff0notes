# 懒标记与区间更新

前置：[[02-数据结构/线段树/01-线段树基础|线段树基础]]。本篇在同一棵树中支持**区间加法、区间赋值，以及区间和、最大值、最小值查询**。

## 适用场景

- 给 $[l,r]$ 每个元素加上 $\Delta$，随后查询任意区间最值或区间和。
- 把 $[l,r]$ 所有元素改为 $v$，并与其他修改、查询交错执行。
- 对一个完整区间的修改，可以直接作用于结点摘要，而且多次修改可以用常数大小的标记合并。

如果所有区间加法都完成后才查询最终数组，用普通差分往往更简单；没有必要为了“区间修改”四个字就直接上懒标记线段树。选型见 [[02-数据结构/线段树/04-区间问题选型与进阶|区间问题选型与进阶]]。

## 核心思想

### 1. 整段覆盖时，先更新摘要，暂缓更新孩子

假设当前结点管理 $[l,r]$，长度为 $\mathrm{len}=r-l+1$。给整段加上 $\Delta$，可以直接更新：

$$
\mathrm{sum}\leftarrow\mathrm{sum}+\Delta\cdot\mathrm{len},\qquad
\mathrm{min}\leftarrow\mathrm{min}+\Delta,\qquad
\mathrm{max}\leftarrow\mathrm{max}+\Delta.
$$

不必立刻下到每一个叶子。先记下“这整段还有一个加法需要传给孩子”，这个记录就是懒标记（lazy tag）。

> [!important] 懒的是孩子的更新，当前结点的答案已经更新
> 整段查询可以立即返回当前统计；部分查询或部分修改需要进入孩子时，才把标记下传。

### 2. 三个动作要区分

- `apply`：把一个修改作用到当前结点的统计，并合并到它的待下传标记。
- `push` / `push_down`：把当前结点的标记作用到两个孩子，再清空当前标记。
- `pull` / `push_up`：从两个孩子重新计算当前结点的统计。

典型顺序：**完整覆盖就 `apply`；部分覆盖先 `push`，递归修改后再 `pull`。**

## 状态定义

复用基础篇的 `Stats { sum, min, max }`。另为每个结点维护：

- `set: Option<i64>`：待执行的赋值；`None` 表示没有赋值标记，`Some(0)` 表示确实要赋值为 $0$。
- `add: i64`：在赋值之后再执行的增量。

标记的语义始终为：**若有赋值就先赋值，再执行加法。** 对单个元素 $x$，标记表示的函数是：

$$
T(x)=
\begin{cases}
v+d,&\text{有赋值 }v\text{，再加 }d,\\
x+d,&\text{没有赋值，只有加法 }d.
\end{cases}
$$

单位标记为 `set = None, add = 0`，表示什么都不做。

## 转移方程

### 1. 赋值如何更新统计

对整段赋值为 $v$：

$$
\mathrm{sum}=v\cdot\mathrm{len},\qquad
\mathrm{min}=\mathrm{max}=v.
$$

若同一标记还包含随后要加的 $d$，再套用加法公式。

### 2. 标记按时间顺序合并

设旧标记为 $T_{\mathrm{old}}$，现在又来了新标记 $T_{\mathrm{new}}$。孩子将来应执行：

$$
T_{\mathrm{combined}}(x)
=T_{\mathrm{new}}\bigl(T_{\mathrm{old}}(x)\bigr).
$$

- **新标记含赋值**：旧修改被覆盖，组合结果直接采用新标记。
- **新标记只有加法**：保留旧赋值，并把新旧增量相加。

例如：

- 先赋值为 $3$，再加 $2$，结果为 $5$。
- 先加 $2$，再赋值为 $3$，结果为 $3$。

所以赋值和加法不能随意交换，也不能把两个标记不分顺序地累加。

### 3. 下传与回收

`push` 时对两个孩子分别 `apply` 同一个组合标记，孩子原有的标记更早、父结点待传的标记更晚。下传后把父结点标记恢复为单位标记，防止重复执行。

部分修改前必须先 `push`，否则稍后的 `pull` 可能用过时的孩子覆盖正确的父结点。

## 初始化与边界

- 接口仍是 1-based 闭区间，构造要求非空数组。
- 新建时所有标记均为 `Tag::identity()`。
- 赋值为 $0$、负数和连续多次赋值都合法；不能用 `set == 0` 判断“没有赋值”。
- 加法允许为负，`add == 0` 是合法的无效果修改。
- 叶子无需再往下传标记。
- 须保证元素值、区间和、长度乘法、标记增量合并等所有 `i64` 中间运算不溢出。
- 本篇只处理赋值和加法；乘负数时最小值、最大值会交换，不能直接照搬这里的公式。

## 遍历顺序

下面代码**复用基础篇的 `Stats` 定义**，与基础代码放在同一模块即可。先只关注 `range_add` 可以理解纯加法版本，再看 `range_set` 和 `Tag::then` 理解标记组合。

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct Tag {
    set: Option<i64>,
    add: i64,
}

impl Tag {
    fn identity() -> Self {
        Self { set: None, add: 0 }
    }

    // 先执行 self，再执行 newer；相当于 newer(self(x))。
    fn then(self, newer: Self) -> Self {
        if newer.set.is_some() {
            newer
        } else {
            Self { set: self.set, add: self.add + newer.add }
        }
    }
}

struct LazySegTree {
    n: usize,
    tree: Vec<Stats>,
    lazy: Vec<Tag>,
}

impl LazySegTree {
    fn new(a: &[i64]) -> Self {
        assert!(!a.is_empty());
        let n = a.len();
        let mut seg = Self {
            n,
            tree: vec![Stats::single(0); 4 * n + 5],
            lazy: vec![Tag::identity(); 4 * n + 5],
        };
        seg.build(1, 1, n, a);
        seg
    }

    fn build(&mut self, p: usize, l: usize, r: usize, a: &[i64]) {
        if l == r {
            self.tree[p] = Stats::single(a[l - 1]);
            return;
        }
        let mid = l + (r - l) / 2;
        self.build(p * 2, l, mid, a);
        self.build(p * 2 + 1, mid + 1, r, a);
        self.pull(p);
    }

    fn pull(&mut self, p: usize) {
        self.tree[p] = Stats::merge(self.tree[p * 2], self.tree[p * 2 + 1]);
    }

    fn apply(&mut self, p: usize, len: usize, tag: Tag) {
        let len = len as i64;
        if let Some(value) = tag.set {
            self.tree[p] = Stats { sum: value * len, min: value, max: value };
        }
        self.tree[p].sum += tag.add * len;
        self.tree[p].min += tag.add;
        self.tree[p].max += tag.add;
        self.lazy[p] = self.lazy[p].then(tag);
    }

    fn push(&mut self, p: usize, l: usize, r: usize) {
        if l == r || self.lazy[p] == Tag::identity() {
            return;
        }
        let mid = l + (r - l) / 2;
        let pending = self.lazy[p];
        self.apply(p * 2, mid - l + 1, pending);
        self.apply(p * 2 + 1, r - mid, pending);
        self.lazy[p] = Tag::identity();
    }

    fn range_add(&mut self, l: usize, r: usize, delta: i64) {
        self.update(l, r, Tag { set: None, add: delta });
    }

    fn range_set(&mut self, l: usize, r: usize, value: i64) {
        self.update(l, r, Tag { set: Some(value), add: 0 });
    }

    fn update(&mut self, l: usize, r: usize, tag: Tag) {
        assert!(1 <= l && l <= r && r <= self.n);
        self.update_inner(1, 1, self.n, l, r, tag);
    }

    fn update_inner(
        &mut self, p: usize, l: usize, r: usize,
        ql: usize, qr: usize, tag: Tag,
    ) {
        if ql <= l && r <= qr {
            self.apply(p, r - l + 1, tag);
            return;
        }
        self.push(p, l, r);
        let mid = l + (r - l) / 2;
        if ql <= mid {
            self.update_inner(p * 2, l, mid, ql, qr, tag);
        }
        if qr > mid {
            self.update_inner(p * 2 + 1, mid + 1, r, ql, qr, tag);
        }
        self.pull(p);
    }

    fn query(&mut self, l: usize, r: usize) -> Stats {
        assert!(1 <= l && l <= r && r <= self.n);
        self.query_inner(1, 1, self.n, l, r)
    }

    fn query_inner(
        &mut self, p: usize, l: usize, r: usize, ql: usize, qr: usize,
    ) -> Stats {
        if ql <= l && r <= qr {
            return self.tree[p];
        }
        self.push(p, l, r);
        let mid = l + (r - l) / 2;
        if qr <= mid {
            self.query_inner(p * 2, l, mid, ql, qr)
        } else if ql > mid {
            self.query_inner(p * 2 + 1, mid + 1, r, ql, qr)
        } else {
            let left = self.query_inner(p * 2, l, mid, ql, qr);
            let right = self.query_inner(p * 2 + 1, mid + 1, r, ql, qr);
            Stats::merge(left, right)
        }
    }
}
```

这里查询使用 `&mut self`，因为部分查询可能下传标记；它改变内部存储状态，但不改变逻辑上的原数组。查询只分发已有修改，不产生新修改，因此不必在返回时额外 `pull`。

手算例子：

1. 初始 $[1,2,3,4,5]$，执行 `range_add(2, 4, 3)`，得到 $[1,5,6,7,5]$。
2. 执行 `range_set(3, 5, 0)`，得到 $[1,5,0,0,0]$。
3. 执行 `range_add(4, 5, -2)`，得到 $[1,5,0,-2,-2]$。
4. `query(1, 5)` 返回 `sum = 2, min = -2, max = 5`。

## 空间优化

- 只需要区间加法时，可删掉赋值标记，保留一个 `add` 数组，模板会更短。
- 只查最值或只查和时，可减少 `Stats` 字段。
- 示例同时保存多种统计和 `Option<i64>`，常数空间比一棵或两棵 BIT 大；大数据题应实际估算内存。

## 复杂度

- 建树：$O(n)$。
- 单次区间加法、区间赋值、区间统计查询：$O(\log(n+1))$。
- 直接读取根结点统计，得到当前全数组答案：$O(1)$；前提是根信息已由更新正常维护。
- 空间：$O(n)$；递归栈：$O(\log(n+1))$。

这些界依赖 `apply`、标记组合和信息合并均为常数时间。并非任意一种“区间更新”都自动满足这个前提。

## 常见错误

- 完整覆盖时只记标记，没有更新当前结点的统计。
- 区间加法更新和时忘记乘区间长度；更新最值时反而错误地乘了长度。
- 部分查询、部分修改前忘记 `push`。
- 下传后忘记清空标记，下一次又重复执行。
- 用 $0$ 充当“没有赋值”的标记，导致赋值为 $0$ 失效。
- 新赋值没有覆盖旧加法，或把“先加后赋值”与“先赋值后加”混为一谈。
- 尚未下传就直接拿孩子做 `pull`，把父结点正确的信息覆盖成旧值。
- 把最大子段和等复杂信息也按“整段加多少，答案就加多少”处理，忽略最优子段长度可能变化。
