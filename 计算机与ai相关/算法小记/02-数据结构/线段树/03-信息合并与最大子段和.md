# 信息合并与最大子段和

前置：[[02-数据结构/线段树/01-线段树基础|线段树基础]]。本篇重点是“结点里究竟存什么”，以及为什么有些查询需要同时维护多个字段。

## 适用场景

- 需要单点修改，并查询某个区间内的最大连续子段和。
- 仅保存区间答案，无法从两个孩子推出父结点答案，需要额外保存边界信息。
- 需要设计自定义线段树，如按排名分类的和、括号匹配、矩阵乘积等。

本篇的“子段”要求连续，且先采用**非空子段**约定。它与可以跳过元素的子序列不同。

## 核心思想

### 1. 只存最大子段和还不够

父区间的最优子段有三种位置：

1. 完全在左孩子内。
2. 完全在右孩子内。
3. 横跨中点，由“左孩子的一段后缀 + 右孩子的一段前缀”组成。

如果只保存左右各自的最优答案，第三种情况就无法计算。因此，必须额外保存最大前缀和、最大后缀和。

### 2. 合并应满足结合律，但不必满足交换律

设 $A,B,C$ 是从左到右相邻的三段。可靠的区间摘要应满足：

$$
\operatorname{merge}(\operatorname{merge}(A,B),C)
=\operatorname{merge}(A,\operatorname{merge}(B,C)).
$$

不同的二分方式只改变括号，不改变答案，这就是结合律。

但交换左右顺序可能改变摘要。最大前缀和、后缀和、括号匹配和矩阵乘积等，都需要保持原数组顺序。基础篇的查询因此总是 `merge(left, right)`。

## 状态定义

对一个非空区间 $[l,r]$，维护四个量：

- `sum`：整个区间的和。
- `pref`：以 $l$ 开始的最大非空前缀和。
- `suff`：以 $r$ 结束的最大非空后缀和。
- `best`：区间内任意非空连续子段的最大和。

`pref`、`suff` 必须贴着区间边界；`best` 可以在区间内部。

## 转移方程

设左右摘要为 $L,R$，合并后的摘要为 $I$：

$$
I.\mathrm{sum}=L.\mathrm{sum}+R.\mathrm{sum},
$$

$$
I.\mathrm{pref}=\max\bigl(L.\mathrm{pref},\ L.\mathrm{sum}+R.\mathrm{pref}\bigr),
$$

$$
I.\mathrm{suff}=\max\bigl(R.\mathrm{suff},\ R.\mathrm{sum}+L.\mathrm{suff}\bigr),
$$

$$
I.\mathrm{best}=\max\bigl(L.\mathrm{best},\ R.\mathrm{best},\ L.\mathrm{suff}+R.\mathrm{pref}\bigr).
$$

解释：父前缀要么完全在左边，要么包含整个左区间再接上右边的一个前缀；父后缀反过来。横跨中点的最优子段就是左最大后缀加右最大前缀。

### 另一个迁移方向：按局部排名分类

现有题卡 [[04-题库/Codeforces/85D-Sum-of-Medians|85D Sum of Medians]] 使用“局部排名模 $5$ 的分类和”。线段树按值域建立，叶子记录某个值是否存在，父结点维护元素数 `count` 和包含 $5$ 个余数类的数组 `f`。

这里统一采用 0-based 局部排名。合并两段时，右段所有元素的排名要增加左段元素数 $c_L$：

$$
f_I[(r+c_L)\bmod5]\mathrel{+}=f_R[r],\qquad r=0,1,2,3,4.
$$

左段分类和保留原位置，元素数相加；每次合并先清空结果数组。它与最大子段和不是同一个模型，但都体现了“保存足够信息，再正确合并”的设计方法。

## 初始化与边界

- 非空子段约定下，值为 $x$ 的叶子初始化为 `sum = pref = suff = best = x`。
- 全负数组的答案是最大的那个元素，例如 $[-5,-2,-7]$ 的答案为 $-2$。
- 若题目允许空子段，叶子的 `pref`、`suff`、`best` 改成 $\max(0,x)$，但 `sum` 仍为 $x$；全负时答案变成 $0$。
- 不要在同一份代码中混用两种约定。
- 无交集查询可以用 `Option<SubarrayInfo>` 表示空区间，合并时直接忽略 `None`，避免对 `i64::MIN` 再做加法而溢出。基础篇只递归有交集孩子的写法也适用。
- 维护的各类和、交叉候选值须能装进 `i64`。

## 遍历顺序

下面是完整的摘要与合并函数，可单独使用。要接入基础篇的树，把结点信息类型换为 `SubarrayInfo`，叶子调用 `single`、父结点调用 `merge`；单点修改和区间划分逻辑不变。

```rust
#[derive(Clone, Copy, Debug, PartialEq, Eq)]
struct SubarrayInfo {
    sum: i64,
    pref: i64,
    suff: i64,
    best: i64,
}

impl SubarrayInfo {
    // 本模板要求子段非空。
    fn single(value: i64) -> Self {
        Self { sum: value, pref: value, suff: value, best: value }
    }

    fn merge(left: Self, right: Self) -> Self {
        Self {
            sum: left.sum + right.sum,
            pref: left.pref.max(left.sum + right.pref),
            suff: right.suff.max(right.sum + left.suff),
            best: left.best.max(right.best).max(left.suff + right.pref),
        }
    }
}

// 线性求整段摘要，适合验证 merge；这不是线段树查询。
fn summarize(a: &[i64]) -> Option<SubarrayInfo> {
    a.iter().copied().map(SubarrayInfo::single).reduce(SubarrayInfo::merge)
}
```

手算 $a=[-2,3,-1,4,-5]$：

- 最大子段为 $[3,-1,4]$，和为 $6$。
- 最大前缀为 $[-2,3,-1,4]$，和为 $4$。
- 最大后缀为 $[3,-1,4,-5]$，和为 $1$。
- 摘要为 `sum = -1, pref = 4, suff = 1, best = 6`。

若在 $[-2,3]$ 与 $[-1,4,-5]$ 之间分割，左最大后缀为 $3$，右最大前缀为 $3$，跨中点答案为 $3+3=6$。

## 空间优化

- 每个结点保存四个 `i64`，总空间仍为 $O(n)$。
- 只做一次静态全数组最大子段和时，可以用 Kadane 算法，时间 $O(n)$、额外空间 $O(1)$，不必建树。
- 需要恢复具体子段位置时，再额外维护边界下标和并列答案的取舍规则。

## 复杂度

- 合并两个四字段摘要：$O(1)$。
- 接入线段树后，建树 $O(n)$，单点修改与区间最大子段和查询均为 $O(\log(n+1))$，树空间 $O(n)$。
- 本篇 `summarize` 是线性扫描，时间 $O(n)$、额外空间 $O(1)$，不要把它当作对数时间的区间查询。
- 排名模 $k$ 的分类和需要 $O(k)$ 合并时间；若 $k$ 为固定常数，线段树更新仍为 $O(\log n)$。

## 常见错误

- 把最大子段和写成 `left.best + right.best`，拼接了中间不连续的两段。
- 只保存 `best`，却没有横跨中点时需要的前缀、后缀信息。
- 把左右孩子顺序交换，或写反 `pref`、`suff` 公式。
- 非空子段题把叶子最大值初始化为 $0$，导致全负时出错。
- 给整段加上 $\Delta$ 时，直接给 `best` 加一个固定量；加法可能改变最优子段长度，这四个字段不能照搬普通区间和的懒更新公式。
- 把能够合并查询信息，误认为也能对任何更新做常数时间 `apply`；这是两个不同的条件。
