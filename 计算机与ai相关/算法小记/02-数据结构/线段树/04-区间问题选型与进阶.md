# 区间问题选型与进阶

## 适用场景

- 题目同时出现“区间”“修改”“最大最小值”，需要判断到底用哪种数据结构。
- 已理解普通线段树，想区分权值线段树、动态开点、可持久化、扫描线和 Segment Tree Beats。
- 希望先利用题目的特殊条件，而不是遇到区间操作就套最复杂的模板。

本篇是选型与进阶入门，不提供这些进阶结构的完整实现；核心可运行模板在 [[02-数据结构/线段树/01-线段树基础|基础篇]] 与 [[02-数据结构/线段树/02-懒标记与区间更新|懒标记篇]]。

## 核心思想

### 1. 先把题目翻译成操作

按顺序确认四件事：

1. **修改是什么？** 单点加、单点赋值、区间加、区间赋值，还是区间逐项取 `min` / `max`？
2. **查询是什么？** 和、最值、计数、第 $k$ 小，还是最大子段和？
3. **什么时候查？** 修改和查询交错，还是全部修改结束后才查最终状态？
4. **数据范围多大？** 下标范围、不同值数、操作数、内存限制分别是多少？

“多次区间修改，最后查询最值”本身还不足以直接决定结构；修改类型和最终查询次数会改变选择。

### 2. 常见选择

| 操作与需求 | 优先考虑 | 说明 |
| --- | --- | --- |
| 静态数组，多次区间和 | 前缀和 | 查询用两个前缀相减 |
| 所有区间加法完成后，再求最终数组 | 普通差分 | 修改两个边界，最后统一前缀累加 |
| 最终数组只查一次全局最大最小值 | 线性扫描 | 无需额外建查询结构 |
| 静态数组，大量区间最大最小值或 GCD | ST 表 | 利用结合律与幂等性，预处理后常数查询 |
| 单点修改，动态区间和或频率计数 | 树状数组 | 线段树也能做，但 BIT 往往更短 |
| 区间加、单点值 | 差分 + 一棵 BIT | BIT 维护差分 |
| 区间加、区间和 | 两棵 BIT 或懒标记线段树 | 根据其他操作和内存选择 |
| 单点修改、动态区间最值 | 普通线段树 | 直接合并区间信息 |
| 区间加或赋值、动态区间和与最值 | 懒标记线段树 | 需要相应的标记及组合规则 |
| 单点修改、区间最大子段和 | 自定义信息的线段树 | 同时维护和、最大前缀、最大后缀、最优子段 |

## 状态定义

### 位置轴与值域轴

- **按位置建树**：叶子对应原数组位置 $i$，维护这个位置上的数及区间统计。
- **按值域建树（权值线段树）**：叶子对应某个值或离散化排名，维护其出现次数、权重等。

两者的树形结构相似，但下标含义不同。查询数组区间的最大值时，树轴通常是位置；维护多重集合第 $k$ 小时，树轴通常是值域。

### 离线得到最终数组

- 区间加法：记录增量差分 $d_l\mathrel{+}=\Delta$、$d_{r+1}\mathrel{-}=\Delta$，前缀累加后与初始数组相加。
- 区间赋值：最终值由最后一次覆盖决定，可以倒序处理赋值，用并查集跳过已经确定的位置；未被覆盖的位置保留初值。
- 赋值与加法混合：不能把两者不分先后累积到同一个普通差分里；懒标记线段树是一个通用选择。

“倒序赋值”是另一套离线实现，不包含在本专题代码模板中；若不熟悉跳点并查集，可以先用已有懒标记模板保证正确性。

## 转移方程

### 1. 静态最值：ST 表

令 $\mathrm{st}[k][i]$ 表示从 $i$ 开始、长度为 $2^k$ 的区间最大值：

$$
\mathrm{st}[k][i]
=\max\bigl(\mathrm{st}[k-1][i],\mathrm{st}[k-1][i+2^{k-1}]\bigr).
$$

查询 $[l,r]$，取 $k=\lfloor\log_2(r-l+1)\rfloor$，用两段可能重叠的区间覆盖目标：

$$
\max(a_l,\ldots,a_r)
=\max\bigl(\mathrm{st}[k][l],\mathrm{st}[k][r-2^k+1]\bigr).
$$

这里能允许重叠，是因为 $\max(x,x)=x$，重复计入不改变结果。最小值、GCD 也有这个性质；**普通区间和不能直接这样查询**，重叠元素会被重复加。

### 2. 权值线段树找第 k 小

结点保存该值域内的频率总数。若左孩子共有 $c$ 个元素：

- $k\le c$：去左孩子找第 $k$ 小。
- $k>c$：去右孩子找第 $k-c$ 小。

前提是所有频率非负，且 $1\le k\le$ 总频率。下降到叶子后还原原值。相同需求也能用 [[02-数据结构/树状数组/03-离散化逆序对与第k小|树状数组倍增]]，不必强行换结构。

### 3. 动态开点与可持久化分别解决什么

- **动态开点**：值域很大时，只为访问到的路径建立结点。未建立的孩子代表该区间的约定初始状态，不等于可以随意忽略它。
- **可持久化线段树**：保留历史版本。一次单点修改仅复制从根到叶子的路径，其余结点与旧版本共享；旧版本不能再原地修改。
- **主席树的常见区间第 k 小模型**：每个前缀建立一份频率版本，对 $[l,r]$ 查询时比较第 $r$ 版与第 $l-1$ 版的计数差，再按左右频率下降。能相减的是计数，不能把两份最大值直接相减来求区间最大值。

动态开点减少没有访问过的区间的存储，可持久化保存版本；它们可以组合，但不是同一件事。

### 4. 扫描线、离散化与树套树

- 扫描线把一维坐标变为事件顺序，另一维用线段树维护。例如矩形面积并要维护覆盖次数与实际覆盖长度，再乘相邻事件的横向间距。
- 几何长度题离散化后，叶子常表示 $[y_i,y_{i+1})$ 的实际区间，长度是 $y_{i+1}-y_i$，不能直接把排名差当作原始距离。
- 树套树在外层结点里维护另一个结构，用于更复杂的二维或动态排名问题；具体时间和空间取决于内外层的组合，不是普通线段树模板自带的功能。

### 5. 区间 chmin / chmax 不一定需要 Segment Tree Beats

`chmin(v)` 表示把每个元素变成 $\min(a_i,v)$；`chmax(v)` 类似。

- **只有区间 `chmin` 与区间最大值查询**：整段最大值可直接变为 $\min(\mathrm{max},v)$，多个上限标记也按 `min` 合并，普通懒标记就能处理。`chmax` 与区间最小值有对称做法。
- **区间 `chmin` 与区间和查询**：仅有区间和、长度不能推出截断后的新和；如果只有最大值和计数，也还要知道次大值，才能判断这次是否只影响最大值那一组。
- **Segment Tree Beats（吉司机线段树）**：典型做法额外维护严格次大值、最大值及其个数等信息，满足条件时批量处理，否则继续递归。若还支持 `chmax`、加法等，信息与分析会继续增加。

以只含 `chmin` 的典型更新为例：设严格次大值为 $\mathrm{max2}$、最大值为 $\mathrm{max1}$。当 $\mathrm{max2}<v<\mathrm{max1}$ 时，只有原最大值那一组被降到 $v$，区间和可减少 $(\mathrm{max1}-v)\cdot\mathrm{countMax}$。$v\ge\mathrm{max1}$ 时无需修改；其他情况需要继续拆分。

这是**有条件的快速更新与均摊分析**，不能笼统宣称任意操作组合都逐次最坏 $O(\log n)$，也不能只看到 `chmin` 就判断必须用 Beats。

## 初始化与边界

- 离线求最终数组时，必须保留未被修改的位置的初值。
- ST 表是静态结构，一次单点修改可能影响大量预处理项；不要边改边直接沿用旧表。
- 离散化保留顺序，不保留距离；是否要恢复原坐标取决于查询含义。
- 动态开点的默认值与查询单位元是不同概念：例如初始全零数组的未建区间最大值是 $0$，无交集查询的最大值单位元却是 $-\infty$。
- 所有进阶结构都需要单独核对题目要求与初始状态，不能把基础篇的字段和标记机械套上。

## 遍历顺序

离线场景通常按下面流程：

1. 读完操作，确认所有查询只关心最终状态。
2. 按修改语义恢复最终数组；加法用差分，纯赋值可考虑倒序跳点。
3. 查询少就直接扫描；大量静态区间最值再建 ST 表，或根据内存选普通线段树。

在线场景按题目给定顺序逐条处理；若题目还用上一次答案解码下一次输入，就不能随意提前排序操作。

## 空间优化

- ST 表通常占 $O(n\log(n+1))$ 空间；普通线段树占 $O(n)$，内存紧张时不必为了常数查询时间强行选 ST 表。
- 动态开点不会自动保证省内存：若访问路径很多，新增结点仍可能很大，要估算总操作数乘路径长度。
- 可持久化结构会保留历史结点，不能按“当前只改一个值”来估算空间。
- 能只扫描最终数组时，不建额外树结构就是最有效的空间优化。

## 复杂度

设数组长为 $n$，修改数为 $q$，最终查询数为 $t$：

- 区间加法差分还原最终数组：$O(n+q)$ 时间，$O(n)$ 空间。
- 还原后仅求全局最大最小值：扫描 $O(n)$，额外空间 $O(1)$。
- 还原后建 ST 表查最值：预处理 $O(n\log(n+1))$，每次查询 $O(1)$，空间 $O(n\log(n+1))$。
- 普通或本专题懒标记线段树：建树 $O(n)$，$q+t$ 次操作总计 $O((q+t)\log(n+1))$，空间 $O(n)$。
- 对值域大小为 $U$ 的动态开点单点更新，通常每次新建 $O(\log(U+1))$ 个路径结点；具体查询与总空间仍依实现和访问模式计算。
- 可持久化单点修改通常每版新增 $O(\log(U+1))$ 个结点；版本总数增长时，这部分空间要累计。
- Segment Tree Beats 与树套树的复杂度按具体操作集合单独证明，本篇不将它们归入普通懒标记的最坏对数保证。

## 常见错误

- 忽略“全部改完才查”，把能用差分的题做成更重的动态结构。
- 认为一旦允许查询穿插修改就只能用某一种结构；树状数组、线段树、分块及题目特性都可能提供解法。
- 把所有“区间修改”都当成加法，忽略赋值的覆盖顺序。
- 对 ST 表的两块重叠查询直接用加法。
- 把按位置的树与按值域的树混为一谈。
- 只要题目出现 `chmin` / `chmax` 就套 Beats，或对 Beats 的所有变种使用同一个复杂度结论。
- 未检查内存，就按完整大值域或多个版本直接分配数组。
