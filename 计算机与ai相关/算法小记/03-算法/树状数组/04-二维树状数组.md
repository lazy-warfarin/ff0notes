# 二维树状数组

前置：[[03-算法/树状数组/01-树状数组基础|树状数组基础]]。先把一维的单点增加和前缀和写熟，再扩展到二维。

## 适用场景

- 网格中的某个格子会被修改，需要反复查询一个矩形内的元素和。
- 动态统计二维坐标中的点数或权重和，且网格规模能够放进内存。

若网格没有修改，二维前缀和预处理后每次查询为 $O(1)$，通常更简单；有动态修改时，二维树状数组才体现优势。

## 核心思想

一维的每个位置负责一个区间，二维的每个位置就负责一个小矩形：

$$
\operatorname{tree}[i][j]
=\sum_{x=i-\operatorname{lowbit}(i)+1}^{i}
\sum_{y=j-\operatorname{lowbit}(j)+1}^{j}a_{x,y}.
$$

行、列各自使用一套 `lowbit` 跳跃：

- 更新 $(x,y)$：两维都向更大的父块跳。
- 查询前缀矩形 $[1,x]\times[1,y]$：两维都向左下标方向拆块。

可以理解为：先在行方向选出要处理的块，再在每个行块中按列方向处理。

## 状态定义

- $n,m$：行数和列数。
- `tree[i][j]`：以 $(i,j)$ 为右下角、行跨度为 $\operatorname{lowbit}(i)$、列跨度为 $\operatorname{lowbit}(j)$ 的矩形和。
- $S(x,y)$：前缀矩形 $[1,x]\times[1,y]$ 的和。
- 约定 $S(0,y)=S(x,0)=0$。

坐标全部为 1-based；输入数组若从 $0$ 开始，调用前先把行列都加 $1$。

## 转移方程

### 单点增加

把 $a_{x,y}$ 增加 $\Delta$，对所有沿更新路径经过的 `tree[i][j]` 加上 $\Delta$。

如果要把这个格子赋值为 $v$，先求旧值再计算增量；旧值可以额外保存，也可以用单格矩形查询得到。

### 矩形求和

查询 $[x_1,x_2]\times[y_1,y_2]$，用二维前缀和的容斥：

$$
\begin{aligned}
\operatorname{rect}&(x_1,y_1,x_2,y_2)\\
={}&S(x_2,y_2)-S(x_1-1,y_2)\\
&-S(x_2,y_1-1)+S(x_1-1,y_1-1).
\end{aligned}
$$

左上角被前两次减法重复减掉，因此最后加回来。

## 初始化与边界

- 零网格初始化 `(n + 1) × (m + 1)` 个 $0$。
- 非零网格可以逐格调用 `add` 建树，这个简单方案需要 $O(nm\log n\log m)$ 时间；下面模板只提供零初始化。
- 更新时，行和列都必须大于 $0$，否则对应维度的循环无法前进。
- 查询允许某个坐标为 $0$，这时前缀矩形为空，结果为 $0$。
- 求和使用 `i64`，须保证各次累加以及容斥过程的中间结果不溢出。
- 这是“单点加、矩形和”模板，不直接支持矩形加法；二维差分、扫描线等需求需要另外推导。

## 遍历顺序

**每次外层循环进入新的一行块，都要把内层列下标恢复到原始的 `y`**。内层循环结束时列下标已经改变，不能直接拿它继续下一轮。

下面代码复用基础篇的 `lowbit` 函数：

```rust
struct Fenwick2D {
    n: usize,
    m: usize,
    tree: Vec<Vec<i64>>,
}

impl Fenwick2D {
    fn new(n: usize, m: usize) -> Self {
        Self { n, m, tree: vec![vec![0; m + 1]; n + 1] }
    }

    fn add(&mut self, x: usize, y: usize, delta: i64) {
        assert!(1 <= x && x <= self.n && 1 <= y && y <= self.m);
        let mut i = x;
        while i <= self.n {
            let mut j = y;
            while j <= self.m {
                self.tree[i][j] += delta;
                j += lowbit(j);
            }
            i += lowbit(i);
        }
    }

    fn prefix_sum(&self, x: usize, y: usize) -> i64 {
        assert!(x <= self.n && y <= self.m);
        let mut result = 0;
        let mut i = x;
        while i > 0 {
            let mut j = y;
            while j > 0 {
                result += self.tree[i][j];
                j -= lowbit(j);
            }
            i -= lowbit(i);
        }
        result
    }

    fn rect_sum(&self, x1: usize, y1: usize, x2: usize, y2: usize) -> i64 {
        assert!(1 <= x1 && x1 <= x2 && x2 <= self.n);
        assert!(1 <= y1 && y1 <= y2 && y2 <= self.m);
        self.prefix_sum(x2, y2)
            - self.prefix_sum(x1 - 1, y2)
            - self.prefix_sum(x2, y1 - 1)
            + self.prefix_sum(x1 - 1, y1 - 1)
    }
}
```

手算检查：在 $3\times4$ 的零网格中，执行 `add(2, 3, 5)` 和 `add(3, 4, 2)`。此时 `prefix_sum(2, 3) == 5`，`rect_sum(2, 3, 3, 4) == 7`，`rect_sum(1, 1, 1, 4) == 0`。

## 空间优化

- 稠密二维 BIT 的空间是 $O(nm)$，坐标范围大时不能直接开表。例如 $10^5\times10^5$ 的坐标域无法用这个模板存储。
- 仅有少量点时，可考虑离线扫描线加一维 BIT，或者逐结点压缩坐标的稀疏二维 BIT。
- 分别离散化行、列后，直接开它们的笛卡尔积表，空间仍然可能很大；离散化不会自动把二维空间变为线性。
- 将二维数组展平为一维连续存储可以减少分配次数，但不改变 $O(nm)$ 的空间级别。

## 复杂度

- 单点增加、前缀矩形和、任意矩形和：$O(\log n\log m)$。
- 零初始化时间、空间：$O(nm)$。
- 更精确地计入空维度和单行、单列时，单次操作的上界可写作 $O(\log(n+2)\log(m+2))$，分配空间为 $O((n+1)(m+1))$。

## 常见错误

- 外层每次进入新块时，没有重新令 `j = y`。
- 行列下标只转换了一维，导致另一维从 $0$ 开始更新。
- 容斥公式最后一项仍写减号，重复减去左上角。
- 把 `(x1, y1, x2, y2)` 的参数顺序写混。
- 只看操作的对数时间，忽略二维数组本身的内存和初始化成本。
- 直接照搬一维差分写法，却没有处理二维的四个边界角点和相应查询公式。
