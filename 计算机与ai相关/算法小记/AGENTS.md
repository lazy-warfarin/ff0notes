# 算法小记 · 协作指南

本仓库是 Obsidian 算法学习仓库：知识点笔记、唯一题目卡片、题单索引三层分离；代码实现在另一个仓库 `D:\projects\Rust\algorithm-notes`。

开始任何任务前，先看 `00-索引/算法总览.md` 和对应专题路线图，确认任务落在哪一层。

## 目录分工

| 目录 | 职责 |
| --- | --- |
| `00-索引/` | 总入口、专题路线图、题目状态看板 |
| `01-基础/` `02-数据结构/` `03-算法/` | 知识点笔记，不复制题目内容 |
| `04-题库/<平台>/` | 每道题唯一一张卡片 |
| `05-题单/<平台>/` | 学习顺序与索引，只放 WikiLink |
| `99-模板/` | 新建文件必须从模板出发 |

## 硬性规则

1. 一题一卡，路径为 `04-题库/{平台}/{contestId}{index}-{Slug}.md`（如 `04-题库/Codeforces/455A-Boredom.md`）。题单和知识点笔记只链接卡片，不复制题意；新建前先查重，如 `rg -n "455A" .`。
2. 题目卡片使用 `99-模板/题目卡片模板.md` 的 14 个 frontmatter 字段；`status` 只用 `todo/doing/solved/redo/mastered`，`priority` 只用 `core/important/challenge`；未实现时 `code_path` 留空。
3. 知识点笔记使用 `99-模板/知识点笔记模板.md` 的章节；"典型题目"只放 WikiLink。正文中文，题目名和术语保留英文原文，文件 UTF-8。
4. WikiLink 一律仓库相对路径，如 `[[04-题库/Codeforces/455A-Boredom|455A Boredom]]`；禁止 `../`；表格单元格里的别名写成 `\|` 转义。
5. 元数据以官方为准：Codeforces 先用 `https://codeforces.com/api/problemset.problems` 核对 title/rating/tags，题面从官方页面抓取核对（直接抓取时带浏览器 UA）；禁止凭记忆写题意、难度和链接。
6. 状态或代码变化后同步 `00-索引/题目状态看板.md`；Dataview 查询是可选增强，任何页面不得强依赖它。
7. 本仓库不放代码工程或 Rust 源码；不提交 `.obsidian/` 等本地配置；编辑保持最小改动，不重构无关目录，不改动用户未提交的内容。
8. Obsidian 数学公式统一使用 MathJax Markdown 语法：行内公式写作 `$...$`，独立公式块使用单独成行的 `$$...$$`；不要使用 `\[...\]` 作为块公式分隔符。正文中的变量、下标、区间和不等式也使用行内公式（如 `$d_i$`、`$[l,r]$`），不要写成裸下标或裸区间；代码标识符仍用反引号，frontmatter 数组和任务列表的方括号保持原样。普通 `[a,b]` 不会自动成为链接，不要机械转义；表格内 WikiLink 别名仍按规则 4 写 `\|`。

## 标准流程

### 新增一道题

1. 查重 → 抓取官方元数据与题面 → 按模板建卡片，先写题意摘要、识别信号、状态与转移、复杂度。
2. 在对应题单和知识点笔记里补上卡片 WikiLink。
3. Rust 实现后回填 `code_path`，更新 `status`、`first_solved`、`next_review`。
4. 做错过的题：写 `failure_reason`，补"复盘"里的关键边界。
5. 同类错误重复出现：补进对应知识点笔记的"常见错误"。

### 新增一个专题（如线段树、树状数组）

1. `00-索引/` 新增专题路线图，并挂到 `算法总览`。
2. 知识点笔记进 `03-算法/<专题>/`，数据结构进 `02-数据结构/`。
3. `05-题单/<平台>/` 建题单；卡片继续复用 `04-题库`，不建平行题库。
4. 复核总览入口与题单、卡片之间的链接闭环。

### Rust 联动（代码在另一个仓库）

- 实现位置 `D:\projects\Rust\algorithm-notes\algs\<专题>\...`，沿用现有命名习惯和 `algs/0输入模板` 的 IO 风格。
- 提交前在该仓库做 `cargo check` 级别的编译验证，不跑无关重构。
- 本仓库只记录 `code_path`；不改动 Rust 仓库，除非用户明确要求。

## 质量检查

- 全库 WikiLink 校验：运行 `scripts/check-wikilinks.ps1`，输出 `unresolved links: 0` 才算通过。
- 卡片完整性：14 个 frontmatter 字段齐全，六个固定章节（题意摘要、识别信号、状态与转移、复杂度、Rust 实现、复盘）齐全。
- 题单一致性：题单和看板引用的卡片必须存在，卡片不能是孤儿。
- 批量格式改动后在 Obsidian 抽查行内公式、表格链接和页面入口的实际渲染。
- 批量改动后复核 `00-索引/算法总览.md` 仍能进入所有路线图。

## 其他约定

- 难度和 tags 会随时间变化，以最新官方数据为准。
- 本仓库尚无历史提交时文件均为未跟踪状态；需要提交先向用户确认。
- 目录结构或约定变化时，同步更新本文件。
